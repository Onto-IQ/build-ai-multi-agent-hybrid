# Module 03 — สำรวจพร้อมกัน โดยยังไม่แก้ของ

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

งานแรกกับโค้ดคนอื่นคือการอ่านให้ครบ ไม่ใช่การแก้ แต่การอ่านเดี่ยวช้าและมุมเดียว มักพลาดเรื่องที่อยู่อีกฝั่งของระบบ เช่น คนอ่านโค้ดเห็นตัวแปร แต่ไม่เห็นว่า CSV จริงพังอยู่ แล็บนี้จึงปล่อย**ผู้ช่วยอ่านอย่างเดียวสามคนทำงานขนานกัน** คนละมุม: โครงเซิร์ฟเวอร์ คุณภาพข้อมูล และด่านตรวจ แล้วบังคับให้รวมเป็นรายงานไฟล์เดียว เหตุผลที่ปลอดภัยคือทุกคนถูกสั่งห้ามแก้ไฟล์ ความเสี่ยงจึงเป็นศูนย์ แต่ได้แผนที่เต็มของแอปภายในไม่กี่นาที

วินัยที่ซ่อนอยู่คือ**รายงานต้องเป็นไฟล์ ไม่ใช่คำเล่าในแชท** ของที่เล่าในแชทตายเมื่อปิดหน้าจอ แต่ไฟล์ใน `docs/` อยู่กับ repo เป็นหลักฐานที่คนถัดไป (และโมดูลถัดไป) อ่านต่อได้

ได้รายงานแล้วจึงถึงตา **Agent Teams**: เพื่อนทีมเป็น Claude คนละชุดความจำ มีรายการงานร่วมและคุยกันเองได้ ไม่ต้องส่งทุกข้อความผ่านหัวหน้า ใช้เมื่ออยากให้พวกเขาท้าทายรายงานและช่วยกันเอง — แพงกว่าคุยคนเดียวประมาณ **15 เท่า** คลาสมีสปอนเซอร์จึงให้ทุกคนลงมือ ไม่ใช่แค่ดูสาธิต

## Concept / เนื้อหา

### Part A — แบ่งมุมยังไง และแต่ละคนเจออะไร (จากเครื่องทดสอบจริง)

คำสั่งก้อนเดียว (ฉบับไทยใน LAB) ปล่อยสามคนขนานกันจบในประมาณ 4 นาที แล้วเขียน `docs/EXPLORATION-REPORT.md` เอง:

| ผู้สำรวจ | มุม | ของจริงที่เจอ |
|---|---|---|
| คนที่หนึ่ง | `server.js` ทีละ endpoint | `/api/summary` ใช้ `split(',')` + อ่านคอลัมน์ `capital_raw` ที่ไม่มีจริง จึงได้ทุน 0 เสมอ; `/api/health` ปล่อย `sampleToken` รูปแบบ `sk-***`; POST `/api/notes` เก็บในหน่วยความจำ และ `JSON.parse` ไม่มี try/catch ทำให้ JSON เสียแล้ว process ตาย |
| คนที่สอง | `data/dataset.csv` เทียบ `data/README.md` | แถวขยะ 9 แถว, `reg_date` พ.ศ. `d/m/2558` ทั้ง 16,772 แถว, `capital` มีลูกน้ำในเครื่องหมายคำพูด, `province` ว่างทุกแถว ต้องเติมจากที่อยู่, `reg_no` ครบ 13 หลักไม่ซ้ำ |
| คนที่สาม | `scripts/quality-gate.js` | เทียบ 6 เคสกับบั๊กของชุดเริ่มทีละข้อ พร้อมเลขบรรทัดอ้างอิง และยืนยันว่า exit 2 คือสภาพตั้งต้นที่ถูกต้อง |

ทุกคนอ้าง `ไฟล์:บรรทัด` ได้จริง นี่คือของที่ทำให้รายงานเชื่อได้ ไม่ใช่เรื่องเล่า

รอบตรวจด้วย claude 2.1.319 ได้ผลสรุปเดิมทุกมุม พร้อมของใหม่จากทีมตรวจรอบสอง: เซิร์ฟเวอร์นับแถวได้ 16,778 ไม่ใช่ "หลายพัน" อย่างที่รายงานว่า เพราะขึ้นบรรทัดใหม่ในเครื่องหมายคำพูดทำหัวตารางภาษาไทยแตก (`data/dataset.csv:4-5`) — ข้อนี้พบตอนทีมทบทวนรายงานใน Part B ไม่ใช่ตอนสำรวจ ระวังเวลา: A จบใน ~30 วินาที แต่ B อาจใช้ ~15 นาทีถ้ามันลงลึกเขียนสคริปต์วิเคราะห์เอง รายงานออกหลังตัวช้าสุดกลับมาเสมอ

### Part B — ของค้นพบที่เกินคำสั่ง

รายงานจริงพบเกินโจทย์ด้วย: ยอดทุนภาค "กลาง" ที่คำนวณ ad-hoc จากไฟล์ดิบได้ `31,680,988,983` แต่ `data/README.md` เขียน `31,680,888,983` ต่างกัน 100,000 พอดี ตอนแรกสงสัยว่า README พิมพ์ผิด — และปมนี้ถูกปิดใน Module 08 เมื่อ SQL มาตรฐานบนไฟล์สะอาดให้ `...888,983` ตรง README เป๊ะ (เลข 988,983 มาจากการกรองแถวที่ไม่เหมือนกัน) บทเรียนคือผลคำนวณ ad-hoc เป็นคำถามที่ดี แต่ต้องยืนยันด้วย pipeline เดียวกับด่านก่อนเชื่อ

### Part C — ทำไมห้ามแก้ในรอบสำรวจ

สำรวจคือการสะสมความเข้าใจ ถ้าปล่อยให้แก้ระหว่างอ่าน ทุกข้อสรุปจะเลื่อนใต้เท้า รายงานปิดท้ายด้วยประโยค "ห้ามแก้ไฟล์ในรอบสำรวจ" เพื่อกุมบรรทัดฐานนี้ไว้ และ `git status` ต้องเห็นแค่ `docs/` ใหม่ ไม่มี `server.js` หรือ CSV ในรายการแก้ไข

### Part D — ผู้ช่วยสำรวจกับเพื่อนทีมต่างกันยังไง

| | Part A — ผู้ช่วยสำรวจ | Part B — Agent Teams |
|---|---|---|
| เปิดยังไง | เปิด `claude` แล้วสั่งได้เลย | ต้องสร้างไฟล์ `.claude/settings.local.json` ก่อน แล้วค่อยเปิด `claude` |
| การคุยกัน | ผู้ช่วยส่งสรุปกลับหัวหน้าเป็นหลัก | เพื่อนทีมคุยกันเองได้ + มีรายการงานร่วม |
| เหมาะกับ | อ่านคนละส่วนแล้วสรุปเป็นไฟล์เดียว | ให้ช่วยท้าทายรายงาน / ถกกันเอง |
| ค่าใช้จ่าย | ถูกกว่าในสองรอบของบทนี้ | แพงกว่ามาก (~15 เท่าของแชทคนเดียว) |
| `claude -p` | ใช้ได้ถ้าจำเป็น | **ใช้ไม่ได้กับโหมดทีม** — ต้องเปิดหน้าจอ `claude` |

ใน Part B ไฟล์ตั้งค่าเปิดโหมดทีมและจำกัดไม่เกิน 20 รอบ — ข้อความเต็มที่ต้องคัดลอกอยู่ที่ [LAB.md](LAB.md) · หลังจบต้องลบไฟล์ `settings.local.json` ก่อนไปโมดูลถัดไป (ไฟล์นี้ไม่หายเองเมื่อปิดหน้าต่าง)

จากเครื่องทดสอบจริง (claude 2.1.319, ~11 นาที): เพื่อนทีมเกิดเป็น background agents มีชื่อครบตามพรอมต์ รุ่นนี้ยังไม่มี team task tools ในตัว ทีมใช้ไฟล์ `TASKS.md` ใน scratchpad ของเซสชันเป็นรายการงานร่วม + log ข้อความ แลกกัน 8 ครั้งก่อน lead สรุป เห็นการเจรจาจริงหนึ่งครั้ง: devil-advocate ค้าน แล้ว data-scout หาข้อเท็จจริงเคลียร์ ข้อค้านจึงย้ายไปฝั่ง agreement data-scout รัน `npm run gate` เอง (exit 2 ตามตั้งต้น) lead ปิดด้วยการนับคำ (238 < 250), รัน `git status`, และส่ง shut down ให้ทุกตัว หน้าถามสิทธิ์เด้งระหว่างทางหลายรอบ เลือกแบบ `allow during this session` / `don't ask again` จะไหลกว่า — และของที่ทีมตรวจเจอเพิ่มจริง ๆ: `ONTOIQ_API_KEY` อยู่แค่ใน `AGENTS.md` ไม่ได้อยู่ใน `CLAUDE.md` ไฟล์กติกาสองฝั่งเลยไม่ตรงกัน (ตรงกับกฎ "แก้ฝั่งหนึ่งอัปเดตอีกฝั่ง" ใน Module 02)

## ลำดับในห้อง (ภาพรวม)

1. วางพรอมต์ก้อนเดียว → ดูมันปล่อยสามคนขนาน → รอจนเขียนไฟล์รายงาน (~4 นาที)
2. ปิด `docs/EXPLORATION-REPORT.md` ด้วยตา: สามหัวข้อ ประโยคปิด ชื่อไฟล์/endpoint ครบ
3. `git status` ยืนยันว่าไม่มีไฟล์แอปถูกแก้
4. รัน `npm run gate` เอง แล้ว `echo $LASTEXITCODE` ต้องได้ `2`
5. Part B — สร้าง `settings.local.json` ตาม LAB → เปิดทีม 3 คนท้าทายรายงาน → ได้ `docs/TEAMS-REVIEW.md`
6. ลบ `settings.local.json` แล้วตรวจ `git status` อีกครั้ง

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 50 นาที

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **เล่าในแชทแต่ไม่เขียนไฟล์** — รอบทดสอบเขียนเองทันที แต่ถ้าเจอเครื่องที่เล่าอย่างเดียว ให้สั่งตามที่ LAB เตรียมไว้: "เขียนลง `docs/EXPLORATION-REPORT.md` ด้วยเครื่องมือ Write จริง"
- **หัวรายงานบอก "Lab 02"** — มันเอาเลขจากแผนที่คลาสใน `CLAUDE.md` ของแอป ซึ่งต่างจากเลขโมดูลของคอร์ส ไม่ใช่ความผิดพลาด ให้ดูสามหัวข้อกับประโยคปิดเป็นเกณฑ์
- **รายงานบอกเลขบรรทัด** — เลขพวกนี้เปลี่ยนได้ถ้ามีคนแก้ไฟล์ภายหลัง อย่าถือเป็นค่าคงที่ ให้ถือเป็นหลักฐาน ณ ตอนสำรวจ
- **พอร์ต 3000 ค้างจากแล็บอื่น** — ถ้าเคย `npm start` ค้างไว้ ด่านจะ FAIL ทั้งกลุ่มเซิร์ฟเวอร์ ปิดก่อนรัน `npm run gate`
- **พรอมต์ Part B ไม่พูดว่า agent team** — ได้ผู้ช่วยสำรวจธรรมดาแล้วคิดว่าจบแล็บแล้ว สั่งใหม่ให้ชัดว่าต้องการเพื่อนทีมที่คุยกันเองได้
- **เปิดทีมแล้วใช้ `claude -p`** — ไม่ได้เพื่อนทีม โหมดทีมต้องเปิดหน้าจอโต้ตอบเท่านั้น
- **ลืมลบ `settings.local.json`** — โมดูลถัดไปอาจยังเป็นโหมดทีมโดยไม่ตั้งใจ ไฟล์นี้ไม่หายเองเมื่อปิดหน้าต่าง
- **Part B ไม่จำกัดจำนวนรอบ** — ทีมวิ่งยาวเกินโดยไม่จำเป็น ใน LAB ใส่เพดาน 20 ไว้แล้ว
- **หน้าถามสิทธิ์เด้งระหว่างทีมทำงาน** — ทีมอ่าน scratchpad นอกโฟลเดอร์โปรเจกต์และรันคำสั่งตรวจ เลือก `allow during this session` / `don't ask again` จะถามน้อยลง
- **เพื่อนทีมรัน gate เอง** — รอบทดสอบ data-scout รัน `npm run gate` เองได้ exit 2 ถูกต้อง แต่หลักฐานสุดท้ายยังต้องมาจากเทอร์มินัลของคุณเสมอ (ขั้น 3 ของ LAB)
- **ขั้น 1 ใช้เวลาไม่คงที่** — A/C จบใน ~30 วินาที แต่ B อาจใช้ ~15 นาทีถ้าลงลึกเขียนสคริปต์วิเคราะห์ CSV เอง ดูแถบ `Waiting for N background agents` แล้วรอ อย่าคิดว่าค้าง

## Quick check / ทบทวน

- ทำไมสามคนอ่านพร้อมกันถึงเร็วกว่าคนเดียวอ่านทีละมุม? — เพราะแต่ละคนมีบริบทโหลดของตัวเอง ไม่ต้องรอคิว และงานอ่านแยกมุมกันได้เต็ม ๆ ไม่ต้องเรียงลำดับ
- อะไรกันความเสี่ยงของการปล่อยสามคนพร้อมกัน? — คำสั่งอ่านอย่างเดียว + ตรวจ `git status` หลังจบ เป็นหลักฐานว่าไม่มีใครลงมือแก้
- รายงานควรมีอะไรเป็นหลักฐาน? — หัวข้อครบตามสั่ง ประโยคปิดบังคับ และการอ้าง `ไฟล์:บรรทัด` ที่กลับไปดูแล้วเจอของจริง
- ทำไม Part B ถึงเปิด Agent Teams ไม่ใช่ผู้ช่วยสำรวจอีกรอบ? — เพราะต้องการให้เพื่อนทีมท้าทายและประสานกันเองผ่านรายการงานร่วม/ข้อความ ไม่ใช่แค่ส่งสรุปกลับหัวหน้า
- ทำไมต้องลบ `settings.local.json` หลัง Part B? — ไฟล์นี้บอก Claude ว่า "เปิดโหมดทีมอยู่" และไม่หายเองเมื่อปิดหน้าต่าง ลืมลบแล้วรอบถัดไปอาจเป็นทีมใหญ่โดยไม่ตั้งใจ
- รายการงานร่วมของทีมอยู่ไหน (รอบทดสอบ claude 2.1.319)? — ที่ไฟล์ `TASKS.md` ใน scratchpad ของเซสชัน รุ่นนี้ยังไม่มี team task tools ในตัว ไฟล์เดียวทำหน้าที่ทั้งรายการงานและ log ข้อความที่ทีมแลกกัน (8 ครั้งในรอบทดสอบ)
