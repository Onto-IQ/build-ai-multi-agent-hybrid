# Module 13 — ให้คนอื่นเปิดดูได้บน Vercel

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ทุกอย่างในสิบสองโมดูลก่อนหน้าอยู่บนเครื่องเรา โมดูลสุดท้ายพาขึ้นของจริงให้คนอื่นเปิดดูได้ และกติกาของโลกจริงเปลี่ยนไปหนึ่งข้อ: **ดิสก์ของ serverless ไม่ถาวร** บนเครื่องเรา ฟีเจอร์โน้ตเขียนไฟล์เพื่อผ่านด่าน 6/6 แต่บน Vercel การเขียนไฟล์คือการหลอกตัวเอง — ของอาจหายระหว่างคำขอ ทางขึ้นที่ถูกคือแยกสองโลกให้ชัด: เครื่องเราเขียนได้, Vercel อ่านอย่างเดียว (405 พร้อมเหตุผล) และ**ไม่ใส่คีย์โมเดลบน Vercel** เพราะของจริงไม่จำเป็นต้องคุยกับโมเดล

หลักฐานสุดท้ายของคอร์สคือ URL: "deploy แล้ว" ในแชทไม่นับ ต้องมี URL ที่เปิดแล้วเห็นของจริง

## Concept / เนื้อหา

### Part A — สิ่งที่ขึ้นจริง (จากเครื่องทดสอบจริง, บัญชี Hobby)

| ชิ้น | หน้าที่ |
|---|---|
| `vercel.json` | ประกาศทางขึ้นและ includeFiles แนบ `data/dataset.csv` (~8 MB) ไปกับฟังก์ชัน |
| `api/summary.js` | ตอบยอดชุดเดียวกับเครื่อง: 16,772 / 45,341,868,784 |
| `api/health.js` | ตอบ `{"ok":true}` — ไม่มี `sk-` ไม่มี sampleToken |
| `api/notes.js` | GET คืนโน้ตตัวอย่าง, POST ตอบ 405 `NOTES_READONLY` — ไม่มี writeFile |

**URL จริง**: https://multi-agent-workshop-hybrid-54svriymv-onto-iq.vercel.app — ตรวจด้วย `vercel curl`: health สะอาด, summary ตรงยอดเป๊ะ, POST โน้ตโดน 405 ตามดีไซน์, `vercel env ls` ว่าง (ไม่มีคีย์) และด่านบนเครื่องยัง 6/6

### Part B — Deployment Protection คือด่านสุดท้ายที่ไม่อยู่ในโค้ด

ค่าเริ่มต้นของ Hobby ปิด URL ด้วย Vercel Authentication — คนที่ไม่ล็อกอินบัญชีเจ้าของจะเจอ 302 ไปหน้า auth นี่ไม่ใช่ความพังของ deploy แต่เป็น**การตัดสินใจระดับบัญชี** ที่ต้องไปเปิดใน Dashboard → Settings → Deployment Protection ระหว่างสอน ให้สาธิตด้วย `vercel curl` พอ — เห็น JSON จริงจาก production โดยไม่ต้องเปิดให้โลกในนาทีนั้น

### Part C — บทเรียนรวมของสองวัน

สองยอดจริงที่ขึ้นบน production คือปลายทางของสายพานทั้งเส้น: ข้อมูลดิบ 16,786 บรรทัดที่พังหลายทาง → สะอาด 16,772 แถวด้วย DuckDB (M05) → server เรียกตัวคำนวณเดียวกับด่าน (M05–06) → ด่าน 6/6 (M06) → รั้วและงบ (M09) → ทีมส่งมอบด้วยไฟล์ (M12) → URL จริง (M13) และทุกขั้นตอนตัดสินด้วยหลักฐานที่รันซ้ำได้ ไม่ใช่คำพูด

## ลำดับในห้อง (ภาพรวม)

1. **บัญชี** — สมัคร/ล็อกอิน Vercel แผน Hobby ในเบราว์เซอร์ (ก่อนวันเรียนดีสุด)
2. **preflight** — gate 6/6 exit 0 (หรือ `@release-manager` จาก M07 ตรวจซ้ำ) → health พอร์ต 3001 ไม่มี `sk-` → `ANTHROPIC_API_KEY` ว่าง → ปิดเซิร์ฟเวอร์
3. **ล็อกอิน CLI ผ่าน prompt** — `npx vercel whoami` ต้องเห็นชื่อบัญชี (ยังไม่ deploy · ไม่แตะ MCP)
4. **deploy ผ่าน prompt** — gate ก่อนเสมอ → `npx vercel --prod` → ได้ URL + commit/deployment id
5. **ยืนยัน** — เปิด URL: แดชบอร์ดขึ้นจริง, health สะอาด, โน้ต 405, ยอดตรงกับ `EXECUTIVE-SUMMARY.md`

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 40 นาที ต้องมีบัญชี Vercel Hobby สมัครไว้ก่อน และ URL จริงที่ขึ้นต้นด้วย `https://` คือหลักฐานปิดคอร์ส — ห้องไหนผู้สอนสั่งหยุดก่อนขึ้นของจริง ให้จบหลัง preflight พร้อมผล gate และบันทึกไว้ว่าขั้น 5–7 เป็นขั้นที่ต้องทำต่อเอง

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **เปิด URL แล้วเจอหน้าล็อกอิน Vercel** — ไม่ใช่ deploy พัง เป็น Deployment Protection ของ Hobby ดู Part B
- **อย่าให้ผู้ช่วย deploy ก่อน gate** — คำสั่งกำหนด "ก่อน deploy ให้รัน npm run gate ถ้าไม่ผ่านให้หยุด" และผู้สั่งต้องเห็น exit code จริง
- **ลืมว่า `npx vercel` ดาวน์โหลด CLI ครั้งแรก** — ครั้งแรกมีคำเตือนติดตั้งแพ็กเกจ ไม่ใช่ error
- **`.vercel/` ห้าม commit** — โฟลเดอร์ที่ CLI สร้างมี project id ฝังอยู่ ให้เพิ่มลง `.gitignore` (รอบทดสอบเพิ่มให้แล้ว)
- **โน้ตที่โพสต์บน production หาย** — ถูกต้อง โน้ตไม่ได้เซฟไว้ที่ใดเลย 405 คือพฤติกรรมที่ตั้งใจ

## Quick check / ทบทวน

- ทำไมไม่เอา server.js ไปฟังพอร์ตบน Vercel? — Vercel รันฟังก์ชันสั้น ๆ ตามคำขอ ไม่มีพอร์ตให้ฟัง ทางที่ถูกคือ `api/*.js` ต่อคำขอ
- ยอดบน production มาจากไหน? — จาก `data/dataset.csv` ที่ถูกแนบไปกับรอบ deploy ผ่าน includeFiles ไม่ใช่จากตัวแปรหรือดิสก์ถาวร
- ทำไมไม่ตั้งคีย์โมเดลบน Vercel? — ของจริงไม่เรียกโมเดล คีย์อยู่ที่เครื่องที่รัน Claude/OpenCode เท่านั้น คีย์ที่ไม่จำเป็นคือคีย์ที่อาจหลุดโดยไม่จำเป็น
