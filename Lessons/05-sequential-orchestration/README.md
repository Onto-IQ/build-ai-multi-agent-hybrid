# Module 05 — สายการผลิต: วางแผนบน OpenCode ลงมือแบบทีมบน Claude

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

งานจริงไม่ใช่คำสั่งก้อนเดียวจบ แต่เป็นสายพาน และสายพานของคลาสนี้วิ่ง**ข้ามเครื่องมือ**: OpenCode วางแผน (บทบาท `planner` เขียนได้ไฟล์เดียวคือ `docs/TASKS.md`) แล้วส่งต่อด้วยไฟล์ให้ทีมของ Claude ลงมือ — `developer.md` เป็นหัวหน้า สร้างเพื่อนทีมสามตัว (data / backend / frontend) คุยกันเองและทำพร้อมกัน จุดที่ต้องอ่านออกคือ**ส่งงานข้ามเครื่องมือได้จริงด้วยไฟล์ใน repo ไม่ต้องแปะข้อความข้ามหน้าจอ**

เหตุผลที่ต้องแยกสายคือ**เคสพังของแต่ละสายอยู่คนละไฟล์** ทำพร้อมกันเมื่อพังจะหายาก ทำทีละสายเมื่อพังรู้ทันทีว่าสายไหน — และเมื่อให้ทีมลงมือพร้อมกัน การแบ่งไฟล์ให้ชัดคือสิ่งที่ทำให้ขนานได้โดยไม่ตอกตัวเอง

สิ่งที่ทำให้สายพานนี้วัดได้คือด่าน: จบโมดูลนี้ด่านต้องเขียว **2 ข้อพอดี** (`data-quality` และ `summary-matches-valid-rows`) ด้วยตัวเลข 16,772 กิจการ / ทุนรวม 45,341,868,784 บาท ส่วนโน้ตกับ health ยังต้องแดง เพราะงานนั้นเป็นของ Module 06 ถ้าผู้ช่วย "ใจดี" ช่วยปิดเคสโน้ตเองด้วย ให้ย้อน — ของล้วนของห้องคือยอมรับว่ายังไม่ครบ

## Concept / เนื้อหา

### Part A — ไฟล์ตัวตนสองฝั่ง และสามสายที่ถือ

| บทบาท | ไฟล์ที่ถือ | ผลงาน (จากเครื่องทดสอบจริง) |
|---|---|---|
| planner (OpenCode, จาก M04) | `docs/TASKS.md` เท่านั้น | แผน 3 สายพร้อม CONSTRAINTS กันแก้ด่าน กันแตะโน้ต/health |
| developer (Claude, ไฟล์ตัวตนใหม่ของแล็บนี้) | ทำตาม task ที่ได้รับ อ้างเลข task | เป็นหัวหน้าทีม ตั้งเพื่อนทีมสามตัวและสรุปผล |
| สาย data | `docs/DESIGN.md`, `scripts/clean-export.sql`, `data/dataset.csv` | SQL อ่าน parquet → กรองแถวขยะ 9 แถว → แปลง พ.ศ.−543 เป็น ISO → ดึงจังหวัดจากที่อยู่ → CSV สะอาด 16,772 แถวเป๊ะ |
| สาย backend | `server.js` จุดเดียว (`/api/summary`) | ทิ้ง parser พัง (`split(',')` + `capital_raw`) ไปเรียก `analyze()` ตัวเดียวกับด่าน — diff สั้น แต่โครงเปลี่ยน |
| สาย frontend | `web/` | โชว์ยอดจริงจาก `/api/summary` พร้อมเครดิต data.go.th |

สายทั้งสามถูกสั่งผ่านบทบาท `developer` ที่มีไฟล์ตัวตน `.claude/agents/developer.md` (tools รวม Bash เพราะต้องลงมือ, ห้ามแตะด่าน) — สายการผลิตจึงเป็นการส่งงานด้วยไฟล์ระหว่างบทบาทที่มีตัวตน (planner.md → TASKS.md → developer.md + ทีม) ไม่ใช่แชทล้วน

### Part B — SQL วนแก้สามรอบ และความหมายของเฉลย

รอบทดสอบจริงโมเดลเขียน SQL พังสามรอบต่อเนื่อง (ชื่อคอลัมน์ผิด → ชนิดข้อมูลชนตอนลบ 543 ปี → ใช้ `REGEXP` เป็นตัวดำเนินการที่ DuckDB ไม่มี) สุดท้ายใช้ของอ้างอิงจาก `node scripts/catch-up.js w3` ผ่านทันที บทเรียนไม่ใช่ "โมเดลไม่เก่ง" แต่คือ **วงจรรัน-ส่ง error-แก้ มีค่าเมื่อใกล้จะโดน** และเฉลยมีไว้ให้ก้าวข้ามจุดคอขวด ไม่ใช่ให้ลอกตั้งแต่ต้น จุดที่ควรเรียนจาก SQL เฉลยคือสามเทคนิค: `strptime(...) - INTERVAL 543 YEAR` สำหรับ พ.ศ., `try_cast(...) IS NOT NULL` กรองแถวขยะใน WHERE, และ `row_number() OVER (... ORDER BY strpos DESC)` เลือกจังหวัดที่ปรากฏใกล้ท้ายที่อยู่ที่สุด

### Part C — สองอุบัติเหตุที่โมดูลนี้สอนโดยไม่ได้ตั้งใจ

1. **ไฟล์กฎที่แชร์กับด่านคือดินระเบิด** — รอบทดสอบโมเดล refactor `parseRows` ใน `lib/inspect-data.js` (ไฟล์กฎที่ด่านเรียกใช้) โดยลืม import ทำให้ด่าน abort ทั้งตัว ก่อนรันด่านรอบสำคัญให้เช็ก `git status` ว่ามีไฟล์กฎถูกแก้หรือเปล่า ถ้ามีและไม่จำเป็น ให้ `git checkout -- lib/inspect-data.js`
2. **พอร์ตค้างจากการทดสอบของผู้ช่วย** — โมเดลรัน `npm start` ทิ้งไว้ ด่านรอบถัดไป FAIL ทั้งกลุ่มด้วย "port 3000 is already in use" ปิดก่อนรันด่านทุกครั้ง

### Part D — โหมดทีมในงานลงมือ (ต่างจาก M03 อย่างไร)

M03 ใช้ทีมกับงาน**อ่าน** (รายงานเดียว) โมดูลนี้ใช้ทีมกับงาน**แก้ของจริง** จึงต้องเพิ่มสามอย่าง: เพดานรอบ 30 (งานยาวกว่า), พรอมต์บังคับขอบเขต "ห้ามช่วยแก้สี่เคสของ M06", และการลบ `settings.local.json` ก่อนรอบรีวิว เพราะรอบรีวิวต้องเป็นงานเดี่ยว ไม่ใช่ทีม — และเพราะงานลงมือมีการเขียนไฟล์จริง สิ่งที่กันขัดแย้งคือ**ไฟล์ที่ถือคนละตัว** (data แตะ SQL/DESIGN, backend แตะ server.js, frontend แตะ web/) ไม่ใช่ความสามัคคีของทีม

## ลำดับในห้อง (ภาพรวม)

1. มี `planner.md` จาก Module 04 → ปิดเปิด opencode ใหม่ (ไฟล์บทบาทโหลดตอนเปิดรอบ)
2. สั่ง planner เขียน `docs/TASKS.md` → ตรวจว่ามีสามสายครบ
3. สร้าง `developer.md` ฝั่ง Claude → ปิดเปิดใหม่อีกครั้ง
4. เปิดโหมดทีม (settings.local.json, MAX_TURNS 30) → สั่ง developer ตั้งเพื่อนทีมสามตัวลงมือสามสาย
5. ลบ `settings.local.json` (บังคับ)
6. สาย data → รัน `duckdb` เอง + `echo $LASTEXITCODE` → นับบรรทัด ~16,773 ดู 3 แถวแรกเป็น ISO
7. `npm start` ดูหน้าเว็บโชว์ 16,772 / 45,341,868,784 แล้ว `Ctrl+C` ปิดก่อนรันด่าน
8. `npm run gate` + `echo $LASTEXITCODE` → PASS 2 ข้อพอดี exit `2`
9. รอบรีวิว: สั่ง developer เขียน `docs/REVIEW.md` เทียบ SQL กับ DESIGN — ห้ามแก้ของ

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 70–80 นาที ต้องมี DuckDB ก่อนเริ่ม

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **planner.md ไม่มี YAML frontmatter** — เคสจากรอบเก่าที่สร้างในโมดูลนี้ (ตอนนี้สร้างที่ Module 04) แต่ยังต้องตรวจด้วยตา: โมเดลเขียน description/mode/permission เป็นหัวข้อ markdown ธรรมดาแล้วลืมบล็อก `---` ไฟล์ไม่ถูกจับเป็น subagent
- **คลิปบอร์ดไทยเพี้ยน (ฝั่ง opencode)** — ตั้งคลิปบอร์ดผ่าน `Get-Content` โดยไม่ใส่ `-Encoding UTF8` แล้วข้อความไทยกลายเป็นตัวมั่วทั้งก้อนถูกส่งไป (เคสจริง: กลายเป็นเรื่อง A/B prefill ที่ไม่เกี่ยว) ดูช่องพิมพ์ใน TUI ก่อนกด Enter เสมอ
- **โมเดล overload วน retry นานสุด ~12 นาทีต่อคำสั่งใหญ่ (ฝั่ง opencode)** — ให้มันลองเอง อย่ากด Esc ถ้ายังเห็น "Retrying ... attempt N"
- **ผู้ช่วยสร้างไฟล์เกินสั่ง** — รอบทดสอบเกินมาเป็น DELIVERABLES/QUICK-START/SUMMARY/VERIFICATION.md ไฟล์ที่ไม่อยู่ในแผนให้ลบทิ้ง อย่าเผลอ commit
- **แก้ lib/inspect-data.js โดยไม่จำเป็น** — ดู Part C ข้อ 1
- **ห้ามลืมว่า backend ยังต้องพังเรื่อง JSON/health/โน้ต** — ถ้าผู้ช่วยแก้พาดพิงถึงสามจุดนี้ ให้ย้อน diff
- **พรอมต์ไม่พูดว่า agent team** — ได้ผู้ช่วยสำรวจธรรมดาแล้วคิดว่าจบ สั่งใหม่ให้ชัดว่าต้องการเพื่อนทีมชื่อชัดเจน
- **ลืมลบ `settings.local.json`** — โมดูลถัดไปอาจยังเป็นโหมดทีมโดยไม่ตั้งใจ ไฟล์นี้ไม่หายเอง
- **พอร์ต 3000 ค้างจากทีมทดสอบเอง** — ปิดก่อนรัน `npm run gate`

## Quick check / ทบทวน

- ทำไม planner ต้องเขียนได้ไฟล์เดียว? — เพื่อให้แผนเป็นของที่ตรวจได้ก่อนแรงงานเริ่ม และกันคนวางแผนลงมือแก้โค้ดเอง
- ทำไมต้องมีไฟล์ตัวตน developer ทั้งที่สั่ง ad-hoc ก็ทำงานได้? — เพราะไฟล์ตัวตนคือสัญญาที่โหลดทุกรอบ (สิทธิ์ bash deny, ห้ามแตะด่าน, อ้างเลข task) สั่ง ad-hoc คือสัญญาที่พิมพ์ใหม่ทุกครั้งและลืมได้
- ทำไม backend จบด้วย diff สั้น? — เพราะทางที่ถูกคือลบ logic สองอย่างที่ทำซ้ำ (parse + นับ) ไปเรียก `analyze()` ตัวเดียวกับด่าน ไม่ใช่เขียนการคำนวณใหม่ให้ตรงเอง
- ด่านควรจบกี่ข้อเขียว ตอนจบโมดูลนี้? — สองข้อพอดี (ข้อมูล + ยอดสรุป) ที่เหลือแดงคือของ Module 06 ถ้าเขียวเกินแปลว่ามีคน "ช่วย" เกินขอบเขต

## Go deeper

- เปิด `docs/TASKS.md` เทียบกับงานจริงที่ทำ ดูว่าแผนกับของจริงต่างกันตรงไหน และเพราะอะไร
- อ่าน SQL ใน `scripts/clean-export.sql` ทีละ CTE แล้วอธิบายได้ว่าทำไมต้อง `row_number()` ตอนเลือกจังหวัด
- รัน `git diff HEAD~1 -- server.js` ดูว่า backend เปลี่ยนแค่ไหน และลองถอดกลับด้วยมือเพื่อเห็นว่าด่านข้อ summary พังกลับทันที
