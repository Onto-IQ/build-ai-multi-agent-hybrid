# Module 12 — ปิดงานเป็นทีม แล้วสรุปให้คนที่ไม่เขียนโค้ด

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

วันสุดท้ายไม่ได้เรียนคำสั่งใหม่ แต่ประกอบทุกอย่างที่ฝึกมาให้เป็นการส่งมอบหนึ่งชุด: ทีมบน Claude Code สี่บทบาท (planner / data-researcher / developer / qa) จัดของให้ตรงกัน แล้วส่งต่อผ่าน**ไฟล์**ให้ OpenCode ที่เป็นคนสรุปด้วยภาษาคน ไม่เกิน 400 คำ สำหรับผู้บริหารที่ไม่เขียนโปรแกรม จุดที่ต้องอ่านออกคือการส่งงานข้ามเครื่องมือทำได้จริงด้วยไฟล์ใน repo — ไม่ต้องแปะข้อความข้ามหน้าจอ

เงื่อนไขกำกับยังเหมือนเดิม: สรุปต้องมีสองยอดจริง (16,772 กิจการ / 45,341,868,784 บาท) ชื่อกรุงเทพมหานคร คำว่ากลาง และสองหัวข้อบังคับ — และ**ห้ามให้ Claude เขียนสรุปผู้บริหาร** คนสรุปคือ OpenCode เพราะคนละบริบทจะกลั่นภาษาคนได้ดีกว่า

## Concept / เนื้อหา

### Part A — สิ่งที่ได้จากทีมสี่บทบาท (จากเครื่องทดสอบจริง)

| บทบาท | ของที่ออก |
|---|---|
| planner | `docs/PRODUCT-SPEC.md` + `docs/TASKS.md` อัปเดตให้ตรงแอปปัจจุบัน (รวมฟีเจอร์ Top 5 จังหวัดจาก Module 11) |
| data-researcher | อ่านอย่างเดียว ยืนยันยอดกับไฟล์ |
| developer | **ไม่ต้องแก้อะไร** — ยอดตรง 16,772 / 45,341,868,784 อยู่แล้ว (แก้ได้เฉพาะเมื่อไม่ตรง) |
| qa | รัน `npm run gate` → 6/6 exit 0 |

ข้อดีอย่างหนึ่งของรอบนี้คือ developer ไม่มีงานแก้ ยอดตรงอยู่แล้ว — ทีมที่ดีไม่แก้ของเพราะรู้สึกว่าควรแก้

### Part B — synthesizer และเงื่อนไขสรุป

สร้างไฟล์ `.opencode/agents/synthesizer.md` (mode: subagent, bash: deny, เขียนได้ไฟล์เดียว) แล้วเรียกใช้เพื่อเขียน `docs/EXECUTIVE-SUMMARY.md` ผลจริงมีครบ: `## ภาพรวมทุนจดทะเบียน` + `## ข้อเสนอแนะ`, ยอด 16,772 / 45,341,868,784, กรุงเทพมหานคร, "พื้นที่กลางประเทศ" — สั้นกว่าเพดาน 400 คำ อ่านจบได้ในหนึ่งจอ

### Part C — ปลายทางของทุกโมดูล

รายงานสำรวจ (M03) กลายเป็นแผน (M05) กลายเป็นของที่ผ่านด่าน (M06) กลายเป็นรายงาน QA (M06) กลายเป็นสรุปสำหรับคนอ่าน (M12) — ทุกขั้นส่งต่อด้วยไฟล์ที่ commit ได้ นี่คือข้อแตกต่างจากการคุยแชท

## ลำดับในห้อง (ภาพรวม)

1. Claude: สั่งสี่บทบาท → ตรวจไฟล์ที่เกิดขึ้น → gate 6/6
2. OpenCode: สร้าง `synthesizer.md` → ตรวจ frontmatter → เรียกใช้เขียน `docs/EXECUTIVE-SUMMARY.md`
3. เปิดสรุปด้วยตา ตรวจสองหัวข้อ สองยอด และความยาว
4. `npm run gate` อีกรอบตอนปิดงาน

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 60 นาที

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **คำสั่งก้อนใหญ่เกินหนึ่งรอบ** — รอบแรกสร้าง synthesizer.md เสร็จ สรุปข้อกำหนดแล้วหยุด ไม่ได้เรียก subagent ทำงาน ต้องเปิดรอบใหม่แล้วสั่งเรียกตรง ๆ ("ใช้ agent synthesizer เขียน docs/EXECUTIVE-SUMMARY.md ...") แยกจังหวะสร้างไฟล์ agent ออกจากจังหวะเรียกใช้เสมอ
- **โมเดล overload ตายกลางทาง** — คำสั่งเรียก synthesizer รอบแรกโดน error ถาวร (3 นาที) ต้องส่งซ้ำ — เหมือน M10
- **สรุปที่แต่งยอด** — ถ้ายอดในสรุปไม่ตรง 16,772 / 45,341,868,784 เป๊ะ ให้ถือว่าสรุปพัง แม้จะอ่านสวย
- **ให้ Claude เขียนสรุปแทน synthesizer** — ผิดผังคลาส ฉบับที่เป็นของส่งมอบต้องมาจาก OpenCode และถูกล็อกให้แตะได้แค่ไฟล์เดียว (สรุปผู้บริหาร = สาย OpenCode ตามผังคลาส) ส่วน `writer` ฝั่ง Claude ใช้ได้เฉพาะขั้นต่อยอดเทียบกับฉบับใน LAB เท่านั้น ไม่ใช่ของส่งมอบ

## Quick check / ทบทวน

- ทำไม developer ไม่มีงานแก้ถึงเป็นเรื่องดี? — เพราะเงื่อนไขของมันคือ "แก้เมื่อยอดไม่ตรงเท่านั้น" ยอดตรง = ไม่มีที่มาของการแก้ ป้องกันการแก้เพราะความรู้สึก
- สรุปผู้บริหารวัดคุณภาพยังไง? — สองยอดจริง + สองหัวข้อ + ไม่เกิน 400 คำ + คนที่ไม่เขียนโค้ดอ่านรู้เรื่อง
- ส่งงานข้ามเครื่องมือได้ยังไงโดยไม่แปะ? — ไฟล์ใน repo: ฝั่งหนึ่งเขียน อีกฝั่งอ่าน

## Go deeper

- เปิด `docs/PRODUCT-SPEC.md` เทียบกับ `docs/TASKS.md` และ `docs/MY-FEATURE-TASKS.md` — เห็นว่า spec หลังบ้านเกิดขึ้นจากงานจริงที่ทำมาทั้งหมด
- อ่าน `docs/EXECUTIVE-SUMMARY.md` ด้วยตาคนที่ไม่ใช่โปรแกรมเมอร์ ถ้าจุดไหนยังเป็นศัพท์เทคนิค ให้สั่งแก้สรุปอีกรอบ
- ดูทุกไฟล์ใน `docs/` รวมกันแล้วเรียงเป็นเรื่องเดียวได้ยังไง (สำรวจ → แผน → ทำ → ตรวจ → สรุป)
