# Module 08 — ต่อ MCP DuckDB อ่านอย่างเดียว แล้ววิเคราะห์จริง

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ถึงตอนนี้ทุกครั้งที่อยากรู้ยอด คุณต้องรัน SQL เองแล้วก็อปผลให้ผู้ช่วย MCP คือปลั๊กที่พลิกบทบาทนี้: ผู้ช่วย**ถามข้อมูลเองได้**ผ่านเซิร์ฟเวอร์ DuckDB ที่จำกัดสิทธิ์อ่านอย่างเดียว ไฟล์ `.mcp.json` หนึ่งไฟล์ที่ราก repo คือทั้งการติดตั้งและการประกาศขอบเขต — ทั้งทีมได้คอนฟิกเดียวกันเมื่อโคลน และเพราะไม่มี `--read-write` ผู้ช่วยจะเก่งแค่ไหนก็แก้ข้อมูลไม่ได้แม้จะลอง

โมดูลนี้จึงเป็นการต่อปลั๊กด้วยมือคุณเองทั้งกระบวนการ: สร้างไฟล์ → อนุมัติใน TUI → ผูกเข้า `data-researcher` → เรียก SQL จริง → รันสคริปต์วิเคราะห์ด้วยมือ → ปิดด้วยเอกสารที่ตัวเลขต้องมาจากไฟล์เท่านั้น

## Concept / เนื้อหา

### Part A — สามชิ้นที่ได้จากโมดูลนี้

| ชิ้น | หน้าที่ | จุดที่ห้ามพลาด |
|---|---|---|
| `.mcp.json` (project scope) | ประกาศเซิร์ฟเวอร์ `data-duckdb` ผ่าน `uvx mcp-server-motherduck` | pin `--python 3.12` (ตัวใหม่ทำ build `cryptography` ล้ม) · **ไม่มี** `--read-write` |
| `mcpServers: data-duckdb` ใน frontmatter ของ `data-researcher` | ให้ตัวสืบค้นเรียก SQL เองได้ | คงบรรทัด `tools` เดิมไว้ · โหลดใหม่ตอนเปิดรอบ |
| `scripts/analysis.sql` → `docs/region-capital.csv` | ยอดต่อภาค (VALUES mapping จังหวัด→ภาค) | รันด้วยมือคุณจากราก repo — หลักฐานไม่ใช่คำเล่า |

### Part B — สองทางถามข้อมูล และทำไมยังต้องมีมือคุณ

| | CLI ด้วยมือคุณ | MCP ผ่านเอเจนต์ |
|---|---|---|
| ใครพิมพ์ SQL | คุณ | เอเจนต์เลือกเอง |
| เหมาะกับ | หลักฐานปิดงาน / ตรวจซ้ำ | สำรวจคำถามเปิด ("ภาคไหนทุนสูงสุด") |
| กฎเดิมยังใช้ | exit code จริงต้องมาจากเทอร์มินัลคุณ | ตัวเลขต้องอ้างไฟล์/ผล query ที่ตรวจซ้ำได้ |

### Part C — ปม 100,000 ที่ปิดในโมดูลนี้

รอบสำรวจ M03 คำนวณภาคกลางได้ `31,680,988,983` แล้วสงสัยว่า `data/README.md` (ที่เขียน `31,680,888,983`) พิมพ์ผิด โมดูลนี้รัน SQL มาตรฐานบนไฟล์สะอาดแล้วได้ `...888,983` **ตรง README เป๊ะ** — เลข 988,983 มาจากการกรองแถวแบบ ad-hoc ที่ไม่เหมือนกับ SQL มาตรฐาน บทเรียน: ผลคำนวณครั้งเดียวเป็นคำถามที่ดี แต่ต้องยืนยันด้วย pipeline เดียวกับด่านก่อนเชื่อ (และ M05 เคยใช้ปมนี้เป็นคำถามตรวจทาน)

## ลำดับในห้อง (ภาพรวม)

1. สร้าง `.mcp.json` (pin Python 3.12) → ตรวจด้วยตา → `uv --version` ต้องใช้ได้
2. เปิด `claude` → อนุมัติ `data-duckdb` → `claude mcp list` ต้องเห็น
3. ผูก `mcpServers` เข้า `data-researcher` → ปิดเปิดใหม่
4. ถาม SQL รายเดือนผ่าน MCP (`TRY_CAST` ไม่ใช่ `CAST`) → ตารางจากข้อมูลจริง
5. สร้าง `scripts/analysis.sql` → รัน `duckdb` เอง + exit code → `docs/region-capital.csv` 6 ภาค
6. `@data-researcher` เขียน `docs/ANALYSIS.md` — ตารางตาม CSV เป๊ะ ห้ามเดา

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 20–30 นาที (ครั้งแรก uvx ดาวน์โหลดแพ็กเกจ) ต้องมี `uv`, ข้อมูลสะอาด และ `data-researcher` จาก Module 04

## Common pitfalls / กับดัก (จากเอกสารและโครงสร้างเฉลย)

- **ตัด `--python 3.12` ทิ้ง** — Python ใหม่ทำ build `cryptography` ล้ม ใช้บล็อกใน LAB เป๊ะ ๆ
- **เผลอใส่ `--read-write`** — ทลายดีไซน์อ่านอย่างเดียวทั้งหมด เช็กว่าไฟล์ไม่มีคำนี้ก่อนอนุมัติ
- **มองข้ามหน้าอนุมัติ** — กล่อง "New MCP server found" ต้องกดอนุญาต ไม่งั้น MCP เงียบ
- **เรียก MCP ทั้งที่ยังไม่รีสตาร์ท** — MCP กับ frontmatter โหลดตอนเซสชันเริ่ม
- **เทียบยอดกับ `data/README.md` แล้วไม่เห็นปม 100,000** — ดู Part C ก่อนสรุปว่าใครผิด
- **เน็ตองค์กรบล็อก uvx** — ครั้งแรกต้องดาวน์โหลดแพ็กเกจ ถ้าบล็อกจริงให้วิทยากรสาธิตบนเครื่องที่ผ่าน (แผนสำรองเดิมของห้อง)

## Quick check / ทบทวน

- ทำไม pin Python 3.12? — กัน build `cryptography` ล้มบน Python ใหม่ ค่านี้อยู่ใน `.mcp.json` จึงต้องคัดลอกทั้งก้อน
- ทำไมไม่มี `--read-write`? — เพราะผู้ช่วยควรอ่านข้อมูลได้อย่างเดียว การเขียนเป็นงานของ pipeline ที่มีด่านกั้น
- ยอดภาคกลางที่ถูกคือเท่าไร? — `31,680,888,983` ตาม SQL มาตรฐานบนไฟล์สะอาด ตรง `data/README.md` (ปมจาก M03 ปิดที่ Part C)
