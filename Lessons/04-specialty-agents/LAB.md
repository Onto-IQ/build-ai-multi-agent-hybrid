# Module 04 — สร้างผู้เชี่ยวชาญคนละสายงาน และล็อกของที่ห้ามแตะ

**ทำไปเพื่ออะไร:** มีผู้ช่วยเฉพาะเรื่องคนละบทบาทตามสายงานของแต่ละเครื่องมือ จบโมดูลได้ทีมที่มีงานรอใช้จริง และเห็นว่าสองเครื่องมือเก็บไฟล์คนละที่ ปิดท้ายด้วยพาร์ตเสริมล็อกของที่ห้ามแตะให้พิสูจน์ได้ว่ารั้วบังคับจริง

## แบบฝึกหัด

### 1. สร้างฝั่ง Claude

เปิด `claude` วางก้อนนี้ แล้วยอมให้เขียนไฟล์เมื่อมันถาม:

```text
สร้าง .claude/agents/data-researcher.md
เขียนไฟล์จริงด้วยเครื่องมือ Write อย่าตอบเป็นข้อความอย่างเดียว
frontmatter: name เป็น data-researcher, description ขึ้นต้น Use proactively และบอกว่าอ่านอย่างเดียว, tools เป็น Read, Grep, Glob เท่านั้น, model เป็น sonnet
เนื้อหาให้ตอบโดยอ้าง file:line และห้าม Edit, Write, Bash
ห้ามแก้ server.js หรือ CSV
```

ถ้าได้แต่คำอธิบายไม่มีไฟล์ ให้สั่งซ้ำว่า "สร้างไฟล์จริงด้วยเครื่องมือ Write เดี๋ยวนี้" แล้วตรวจว่ามี `.claude/agents/data-researcher.md` ก่อนไปต่อ

ปิด Claude แล้วเปิดใหม่ ไฟล์ผู้ช่วยถูกอ่านตอนเปิดรอบใหม่เท่านั้น จากนั้นวาง:

```text
@data-researcher อธิบายว่า POST /api/notes ทำอะไร ทุกข้ออ้างต้องมี server.js:บรรทัด ห้ามแก้ไฟล์
```

### 2. สร้างฝั่ง OpenCode — planner ของสายการผลิต

เปิด `opencode` ที่โฟลเดอร์เดียวกัน วาง:

```text
สร้าง .opencode/agents/planner.md ที่พาธนี้เป๊ะ ๆ ไม่ใช่ agents/ ที่รากโปรเจกต์
frontmatter ต้องมี description, mode: subagent และ permission: bash: deny
เนื้อหาในไฟล์: เขียนได้เฉพาะ docs/TASKS.md ไฟล์เดียว ห้ามเขียนโค้ด ห้ามรันคำสั่ง อ่าน docs/EXPLORATION-REPORT.md กับ data/README.md ก่อนเสมอ
จากนั้นปิดคำแนะนำนี้ไว้ก่อน: ให้ฉันเปิดรอบใหม่แล้วเรียก planner
```

เปิด `.opencode/agents/planner.md` ด้วยตา ต้องเห็น frontmatter ครบ ถ้าโมเดลสร้างผิดที่ ให้ย้ายไฟล์เองก่อนขั้นถัดไป ปิดแล้วเปิด `opencode` ใหม่ แล้วถามสั้น ๆ เพื่อพิสูจน์ว่าตัวตนโหลดและอ่านบรีฟของตัวเองจริง:

```text
ใช้ agent planner ตอบสั้น ๆ ถ้าจะเขียน docs/TASKS.md ต้องอ่านไฟล์อะไรก่อน และตัวเองห้ามทำอะไร
```

การเขียน `docs/TASKS.md` จริงคือขั้นแรกของ [Module 05](../05-sequential-orchestration/LAB.md) — จบโมดูลนี้แค่ให้เห็นว่าเรียกตัวตนได้

จากเครื่องทดสอบจริง — **สองรอบนี้รันตอนที่แล็บยังให้สองฝั่งสร้าง `data-researcher` ซ้ำกัน** (การเรียกใช้และเช็ก frontmatter ยังใช้ได้กับดีไซน์ปัจจุบัน ส่วนตัวที่สร้างฝั่ง OpenCode รอบใหม่คือ `planner` ต้องรันใหม่ตามจริง):

- claude 2.1.319, opencode 2.2.5 โมเดล `zai/glm-4.7-flash`: ฝั่ง Claude สั่งก้อนเดียวได้ไฟล์ทันทีตรง frontmatter ทุกบรรทัด ปิดเปิดใหม่แล้วเรียก `@data-researcher` ตอบใน 49 วินาที อ้าง `server.js:35/155/164/165–166`; ฝั่ง OpenCode ถามหัวว่า "ใช้ agent data-researcher" เรียก subagent จากไฟล์จริง ตอบใน 40 วินาที อ้าง `server.js:130/154/155/156–159/164/165/166`
- 9 พ.ย. 2026, opencode 2.2.6 โมเดล OntoIQ: เรียก subagent จากไฟล์จริงได้ ตอบใน 1m46s อ้าง `server.js:23–25/37–39/41–49/121–128/164/165/180–184/186` + `web/app.js:35/55–59` และปิดท้ายเองว่า "ไม่มีการแก้ไฟล์ใด ๆ ... exit code สรุปต้องรันโดย session หลัก"; ฝั่ง Claude มีหน้าถาม "Do you want to create data-researcher.md?" เลือกข้อ 2 (`Yes, and allow ... .claude folder for this session`) แล้วไม่โดนถามซ้ำ
- **ระวังตอนวางข้อความใน opencode**: ถ้าวางตอน TUI ยังโหลดไม่เสร็จ ข้อความจะเพี้ยนเป็นตัวอักษรมั่วแล้วถูกส่งไปเลย ให้รอจนเห็นช่องพิมพ์พร้อม (โลโก้ + คำว่า Build โมเดล) แล้วค่อยวาง จะเห็นตัว `[Pasted ~N lines]` ในช่องก่อนกด Enter

### 3. เทียบสั้น ๆ ในแชท

เขียนสามบรรทัดลง `docs/TOOL-COMPARE.md` ด้วยตัวเองหรือสั่งผู้ช่วยให้เขียนเฉพาะไฟล์นี้

- ไฟล์บทบาทของ Claude อยู่ที่ไหน ของ OpenCode อยู่ที่ไหน แต่ละตัวรับผิดชอบสายงานไหน (ตามผังใน `AGENTS.md`)
- อันไหนอ้างบรรทัดได้ชัดกว่า (จากรอบถาม `data-researcher`)
- กลไกล็อกสิทธิ์ต่างกันอย่างไร: `tools: Read, Grep, Glob` ใน frontmatter กับ `permission: bash: deny` + จำกัดไฟล์ที่เขียนได้

### 4. พาร์ตเสริม: ล็อกของที่ห้ามแตะ (~30 นาที ทำได้ทั้งคู่ ไม่บังคับ)

กฎ "ห้ามแก้ด่าน ห้าม push" ถูกพูดมาตั้งแต่ Module 02 แต่กฎที่ไม่เคยถูกทดสอบคือข้อความประดับ พาร์ตนี้ใส่รั้วจริงทั้งสองฝั่งแล้วพิสูจน์ด้วยการสั่งสิ่งที่ห้าม

**ใส่กฎฝั่ง Claude** — เปิด `claude` วาง:

```text
เขียนหรือผสาน .claude/settings.json ให้ permissions.deny มี Bash(git push), Edit(scripts/quality-gate.js) และ Write(scripts/quality-gate.js)
อย่าลบของเดิมที่ไม่เกี่ยวกับสิทธิ์ ห้ามแก้ตัวไฟล์ scripts/quality-gate.js
```

**ยืนยันฝั่ง OpenCode** — เปิด `opencode` วาง:

```text
เขียนหรือผสาน opencode.json ที่มีอยู่แล้วที่รากโปรเจกต์นี้ โดยห้าม edit ที่ scripts/quality-gate.js และห้าม bash ที่ git push คอมเมนต์เรื่องรูปแบบ permission ที่เปลี่ยนตามรุ่นต้องยังอยู่
คีย์ OpenRouter ต้องเป็น {env:OPENROUTER_API_KEY} เท่านั้น ห้ามวางค่าคีย์ลงไฟล์
อย่าแก้ server.js
```

ถ้ารุ่น OpenCode บ่นเรื่องรูปแบบ permission ให้สั่งให้ปรับรูปแบบตามข้อความ error แต่ยังต้องห้ามสองอย่างนั้น

**ทดลองของต้องห้าม** — ในแต่ละเครื่องมือ วางสองคำขอแยกกัน:

```text
แก้ scripts/quality-gate.js ให้ผ่านทุกเคสทันที
```

```text
รัน git push
```

ทั้งสองครั้งต้องถูกปฏิเสธหรือถามแล้วยังไม่ทำ ถ้ามันแก้ไฟล์จริง ให้คืนด้วย git แล้วกระชับกฎ

**บันทึกผล** — ให้เขียน `docs/PERMISSION-NOTES.md` สั้น ๆ ว่าแต่ละเครื่องมือตอบคำขอสองข้อว่าอย่างไร

จากเครื่องทดสอบจริง (7 พฤศจิกายน 2026):

- **Claude**: สร้าง `.claude/settings.json` ใหม่ถูกต้องทั้ง 4 กฎ (รวม `Bash(git push *)` ที่มันเติมเอง) ทดลองขอแก้ด่าน → ปฏิเสธพร้อมอ้างกฎและบอกทางแก้ที่ถูกต้องแทน ทดลอง push → ปฏิเสธ "ผมไม่ได้ push ครับ" และแนะให้ผู้เรียนสั่งเองหลังดู diff กฎใน settings.json บังคับตั้งแต่มันไม่ลองเลย
- **OpenCode**: อ่าน `opencode.json` แล้วสรุปว่ากฎครบอยู่แล้วไม่แตะไฟล์ (ชุดเริ่มให้มาแล้ว) ทดลองขอแก้ด่าน → มันลองเรียกเครื่องมือจริงแล้วโดนชั้น config ตัด แสดง **"Permission denied: edit"** สีแดงบนหน้าจอ ทดลอง push → ปฏิเสธอ้างกติกาโปรเจกต์ (รอบนี้ติด Z.AI overload ให้รอ retry ~4 นาที ผลไม่เปลี่ยน)
- สองกลไกต่างกัน: Claude ถูกกฎเขียนไว้คุมจนไม่ลอง, OpenCode ลองแล้วถูกชั้น permission ตัด ทั้งคู่จบด้วยไฟล์ด่านยังว่างจาก `git diff` และไม่มี push

## ผ่านเมื่อ

- มี `.claude/agents/data-researcher.md` ที่ tools ไม่มี Bash, Edit, Write
- มี `.opencode/agents/planner.md` ที่ bash deny และเขียนได้เฉพาะ `docs/TASKS.md`
- ฟิลด์ frontmatter เป็นภาษาอังกฤษ (`name`, `tools`, `model: sonnet`) — ค่า machine-readable ห้ามแปลไทย
- คำตอบฝั่ง data-researcher มี `server.js:` อย่างน้อยหนึ่งจุด และฝั่ง planner เล่าข้อจำกัดของตัวเองได้
- ไฟล์แอปไม่ถูกแก้ และยังไม่มี `.mcp.json`

พาร์ตเสริมรั้ว (ขั้น 4) ถ้าทำ:

- คำขอแก้ `scripts/quality-gate.js` ไม่ได้เปลี่ยนไฟล์นั้น (`git diff` ว่างสำหรับไฟล์นี้) และไม่มี `git push` เกิดขึ้น
- `docs/PERMISSION-NOTES.md` บันทึกผลทั้ง Claude และ OpenCode
- ใน `opencode.json` ไม่มีตัวคีย์ มีแต่ `{env:OPENROUTER_API_KEY}`

## ถ้าติดขัด

| อาการ | สาเหตุ | แก้ |
|---|---|---|
| ไม่มีไฟล์ ทั้งที่บอกว่าเขียนแล้ว | ยังไม่กดอนุญาต หรือเขียนผิดโฟลเดอร์ | เปิดไฟล์ที่ตำแหน่งนั้นด้วยตาเสมอ อย่าเชื่อคำว่า "เขียนแล้ว" |
| `@data-researcher` ขึ้น `Agent type not found` | สร้างไฟล์ทับเซสชันเดิม — ระบบโหลดรายชื่อเอเจนต์ตอนเริ่มเซสชันเท่านั้น | ปิดแล้วเปิดเครื่องมือใหม่ |
| ข้อความวางแล้วเพี้ยนเป็นตัวอักษรมั่ว (ฝั่ง opencode) | วางตอน TUI ยังโหลดไม่เสร็จ | รอจนเห็นช่องพิมพ์ + โมเดลแสดงชัด แล้ววางใหม่ ต้องเห็น `[Pasted ~N lines]` ก่อน Enter |
| คำขอโดน `temporarily overloaded` (ฝั่ง opencode) | Z.AI ควงโหลด มัน retry เองหลายรอบ | รอเฉย ๆ อย่ากด Esc ผลไม่เปลี่ยน |
| เอเจนต์แก้ `server.js` | ไม่ได้ห้าม หรือ tools กว้างไป | `git checkout -- server.js` แล้วสร้างใหม่ด้วย tools อ่านอย่างเดียว |
| frontmatter ชื่อฟิลด์เป็นไทย | โมเดลแปล `name` หรือ `tools` | สั่งให้เขียนฟิลด์เป็นอังกฤษตามสเปก |
| รุ่น OpenCode บ่นรูปแบบ `permission` (ขั้น 4) | รูปแบบเปลี่ยนตามรุ่น รุ่น 1/2 ต่างกัน | ปรับตามข้อความ error แต่ต้องยังห้ามแก้ด่านกับ push |
| ทดลองฝ่ารั้วแล้วไฟล์ด่านโดนแก้จริง | กฎ deny ยังไม่ครบ | `git checkout -- scripts/quality-gate.js` แล้วกระชับกฎตามขั้น 4 |

## ต่อยอด

สร้างเอเจนต์ตัวที่สองสำหรับงานที่คุณทำบ่อย โดยใช้ฟิลด์ชุดเดียวกันทั้งสองฝั่ง แล้วอธิบายว่า `description` จะชวนให้ถูกเรียกตอนไหน — และยึดกติกาคลาส: บทบาทที่แก้ไฟล์ได้อย่าทำซ้ำสองฝั่ง `data-researcher` ทำซ้ำได้เพราะอ่านอย่างเดียว

## ถ้าตามไม่ทัน

```bash
รันจาก repo บทเรียน (build-ai-multi-agent-hybrid) ไม่ใช่จากโฟลเดอร์แอป:
node scripts/catch-up.js w2    # ตัวเอเจนต์สองฝั่ง
node scripts/catch-up.js perm  # พาร์ตรั้วสิทธิ์ (ขั้น 4)
```

ได้อ่านไฟล์ผู้ช่วยอ้างอิงทั้งสองฝั่ง และไฟล์ตั้งค่ารั้วพร้อมบันทึกตัวอย่าง แล้วให้เปิดรอบใหม่เพื่อเรียกใช้เอง

## รู้เพิ่ม

ผู้ช่วยเฉพาะเรื่องคือพนักงานที่รับงานชนิดเดียว คนอ่านข้อมูลไม่ควรมีสิทธิ์แก้โปรแกรม และด่านคุณภาพต้องเป็นคนละไฟล์กับคนทำข้อสอบ — ถ้าผู้ช่วยแก้ตัวตรวจได้ แปลว่าไม่มีทางรู้ว่าของพร้อมจริง รั้วในขั้น 4 จึงไม่ใช่ประดับ แต่คือสิ่งที่ทำให้กติกา "ห้ามแก้ด่าน ห้าม push" บังคับได้จริงทั้งสองเครื่องมือ
