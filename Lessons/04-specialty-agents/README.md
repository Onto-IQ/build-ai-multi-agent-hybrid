# Module 04 — ผู้เชี่ยวชาญ และเส้นสิทธิ์

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ผู้ช่วยทั่วไปทำได้ทุกอย่าง อ่าน แก้ รันคำสั่ง ซึ่งดีตอนทำงาน แต่เป็นอันตรายตอนสำรวจข้อมูล เพราะมันอาจ "ช่วย" แก้ข้อมูลให้ตัวเองโดยไม่บอก แล็บนี้จึงสร้าง**พนักงานตำแหน่งเดียว**: `data-researcher` ผู้เชี่ยวชาญที่มีสิทธิ์อ่านอย่างเดียว สิทธิ์ถูกเขียนไว้ใน frontmatter ของไฟล์บทบาท ไม่ใช่แค่คำสั่งในแชท คำสั่งในแชทตายเมื่อปิดหน้าจอ สิทธิ์ในไฟล์อยู่กับ repo

ข้อสังเกตสำคัญของห้องไฮบริดคือ**สองเครื่องมือเก็บไฟล์บทบาทคนละที่และทำคนละสายงาน**: Claude เก็บที่ `.claude/agents/`, OpenCode เก็บที่ `.opencode/agents/` และรูปแบบล็อกสิทธิ์ก็ต่างกัน — Claude ใช้ `permissions.deny` ใน `settings.json`, OpenCode ใช้บล็อก `permission` ใน `opencode.json` บทนี้จึงให้**คนละบทบาทตามสายงาน**: Claude สร้าง `data-researcher` นักสืบค้นอ่านอย่างเดียว (ถูกเรียกใช้จริงใน Module 12), OpenCode สร้าง `planner` คนวางแผนสายการผลิต (ถูกเรียกใช้ทันทีใน Module 05) — จบโมดูลได้ทีมที่มีงานรออยู่ ไม่ใช่ตัวอย่างซ้ำสองก้อน

ครึ่งหลังของโมดูล (เส้นสิทธิ์) คือการ**พิสูจน์ว่ากลอกใช้ได้จริง** ด้วยการสั่งสิ่งที่ห้ามแล้วดูมันปฏิเสธ กฎที่ไม่เคยถูกทดสอบคือข้อความประดับ

## Concept / เนื้อหา

### Part A — ไฟล์บทบาทสองฝั่ง (จากเครื่องทดสอบจริง)

| ฝั่ง | ไฟล์ | กลไกล็อกสิทธิ์ |
|---|---|---|
| Claude Code | `.claude/agents/data-researcher.md` | `tools: Read, Grep, Glob` ใน frontmatter — เรียกใช้ด้วย `@data-researcher` หลังเปิดรอบใหม่ |
| OpenCode | `.opencode/agents/planner.md` | `mode: subagent` + `permission: bash deny` เขียนได้เฉพาะ `docs/TASKS.md` — เรียกด้วยคำว่า "ใช้ agent planner" หลังเปิดรอบใหม่ |

ฝั่ง data-researcher ตอบคำถาม `POST /api/notes` โดยอ้าง `server.js:บรรทัด` จริง (รอบเดิม 49 วิ / รอบ 2.2.6 ใหม่ 1m46s อ้างละเอียดถึง 10 จุด) ฝั่ง planner พิสูจน์ด้วยการให้เล่าข้อจำกัดของตัวเอง — อ่านอะไรก่อน ห้ามอะไร — ตัวตนโหลดและอ่านบรีฟตัวเองจริง

### Part B — เส้นสิทธิ์: กฎอยู่ไฟล์ไหน บังคับตรงไหน

| กฎ | อยู่ที่ | ผลตอนทดลองจริง |
|---|---|---|
| ห้ามแก้ด่าน | Claude: `Edit(scripts/quality-gate.js)` + `Write(...)` ใน `.claude/settings.json` | ปฏิเสธตั้งแต่ไม่ลอง อ้างกฎ แล้วชี้ทางแก้ที่ถูกต้องแทน |
| ห้ามแก้ด่าน | OpenCode: `permission.edit.deny` ใน `opencode.json` | มันลองเรียก Edit จริง แล้วระบบแสดง **"Permission denied: edit"** — เห็นกับตาว่าชั้น config ตัด |
| ห้าม push | Claude: `Bash(git push)` + `Bash(git push *)` | ปฏิเสธ พร้อมแนะให้ผู้เรียนสั่งเองหลังดู diff |
| ห้าม push | OpenCode: `permission.bash.deny` | ปฏิเสธอ้างกติกาโปรเจกต์ แนะให้ผู้เรียนรันเอง |

ใจความ: **สองชั้นกันซ้อนกัน** — ชั้นกฎที่เขียนบอก (ไฟล์กติกา + frontmatter) ทำให้ส่วนใหญ่ไม่ลอง ชั้น config (settings/opencode.json) คือกำแพงจริงเวลามันลอง

### Part C — ผลจาก `docs/`

รอบทดสอบเขียน `docs/TOOL-COMPARE.md` (เทียบตำแหน่งไฟล์ ความชัดของการอ้างบรรทัด ความพยายามแก้ไฟล์) และ `docs/PERMISSION-NOTES.md` (ตารางคำขอต้องห้ามสี่กรณีพร้อมหลักฐาน) — สองไฟล์นี้คือสมุดบันทึกที่วัดได้

## ลำดับในห้อง (ภาพรวม)

1. สร้าง `data-researcher` ฝั่ง Claude → ปิดเปิดใหม่ → `@data-researcher` ถามเรื่อง `POST /api/notes`
2. สร้างฝั่ง OpenCode → ปิดเปิดใหม่ → ถามคำถามเดียวกัน → เทียบการอ้างบรรทัด
3. เขียน `docs/TOOL-COMPARE.md`
4. เส้นสิทธิ์: ใส่ deny ทั้งสองฝั่ง → ทดลองขอแก้ด่านและ push ในแต่ละเครื่องมือ → เขียน `docs/PERMISSION-NOTES.md`

แบบฝึกหัดเต็มอยู่ใน [LAB.md](LAB.md) ไฟล์เดียว: ผู้เชี่ยวชาญ ~50 นาที + พาร์ตรั้วสิทธิ์ (ขั้น 4) ~30 นาที

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **ไฟล์บทบาทไม่โหลด** — เรียก `@data-researcher` แล้วไม่มีใครตอบ มักเพราะยังไม่ปิดเปิดเครื่องมือใหม่ ไฟล์ถูกอ่านตอนเปิดรอบใหม่เท่านั้น
- **วางข้อความตอน opencode ยังโหลด** — ข้อความเพี้ยนเป็นตัวอักษรมั่ว ("Bov2bMYSZ8BO" คือของจริงจากรอบทดสอบ) แล้วถูกส่งไปเป็น session ขยะ ให้รอจนเห็นช่องพิมพ์พร้อม + โมเดลแสดงชัด แล้วค่อยวาง เห็น `[Pasted ~N lines]` ก่อนกด Enter
- **โมเดล overload** — คำขอบางคำโดน "The service may be temporarily overloaded" แล้ว retry เองหลายรอบ (~4 นาทีในรอบ push test) ให้รอ อย่ากด Esc ผลลัพธ์ไม่เปลี่ยน
- **เผลอเพิ่มบทบาทในสองฝั่งที่ชื่อเดียวกันแต่แก้ได้** — ยึดกติกาคลาส: บทบาทแก้ไฟล์อย่าใช้ชื่อซ้ำสองฝั่ง แล็บนี้คนละชื่อ (data-researcher / planner) จึงไม่มีปัญหา ถ้าเพิ่มบทบาทเองให้ยึดกติกานี้ต่อ
- **ลืมว่า opencode.json มีกฎมาแล้ว** — ชุดเริ่มใส่ deny ด่านกับ push มาให้ รอบทดสอบโมเดลสรุป "ครบแล้ว ไม่แตะ" ซึ่งถือว่าผ่าน ไม่ต้องบังคับให้เขียนซ้ำ
- **เชื่อคำว่า "เขียนแล้ว" โดยไม่เปิดไฟล์** — เคยมีรอบที่เอเจนต์รายงานว่าเขียนเสร็จทั้งที่ไฟล์ไม่มีจริง เปิดด้วยตาทุกครั้งจึงไม่ใช่ตัวเลือก
- **frontmatter ค่า machine-readable เป็นไทย** — `name`/`tools`/`model` ต้องเป็นอังกฤษตามสเปก คำอธิบายในเนื้อไฟล์เป็นไทยได้

## Quick check / ทบทวน

- ทำไมสิทธิ์ต้องอยู่ในไฟล์ ไม่ใช่คำสั่งในแชท? — เพราะไฟล์โหลดทุกรอบและ commit ได้ คำสั่งแชทอยู่แค่รอบเดียว
- "Permission denied: edit" ของ OpenCode แปลว่าอะไร? — แปลว่าโมเดลพยายามเรียกเครื่องมือ แต่ชั้น config ใน `opencode.json` ตัดก่อนทำจริง คือกำแพงที่ทำงานจริง
- ทำไมให้คนละบทบาท แทนที่จะทำซ้ำสองฝั่ง? — ทำซ้ำได้แค่ค่าเรียนรู้เรื่องรูปแบบไฟล์ แต่คนละบทบาทให้ทีมที่มีงานรอจริง: planner โดนเรียกทันทีใน Module 05 data-researcher โดนเรียกใน Module 12

## Go deeper

- เปิด `.claude/settings.json` แล้วลองเอา `Bash(git push *)` ออกหนึ่งบรรทัด รันทดสอบ push ซ้ำ แล้วเทียบพฤติกรรม
- อ่าน `docs/PERMISSION-NOTES.md` ร่วมกัน แล้วถามว่าถ้าโมเดลใหม่ลองแก้ด่านด้วยเครื่องมืออื่นที่ไม่ใช่ Edit/Write เช่น Bash เขียนไฟล์ กฎเรายังครอบไหม
- ดู `docs/TOOL-COMPARE.md` แล้วคุยว่าห้องนี้ควรใช้ใครเป็นคนถามข้อมูลประจำ และเพราะอะไร
