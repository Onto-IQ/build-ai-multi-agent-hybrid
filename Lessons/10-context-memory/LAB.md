## Part A — ฝั่ง Claude: `memory: project` จำแยกบทบาท

### 1. เปิด memory ให้สองตัวที่ได้ประโยชน์ชัด

เปิด `claude` วาง (เลือกอย่างหนึ่ง) แล้วกดอนุญาตเมื่อแก้ `.claude/`:

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
Add memory: project to the frontmatter of both .claude/agents/data-researcher.md and .claude/agents/qa.md. Keep name, description, tools, and any mcpServers line on each file exactly as they are. Do not change the bodies. Do not add memory to developer or release-manager.
```

**เวอร์ชันไทย (ใช้ได้ผลเท่ากัน):**

```text
เพิ่ม memory: project ใน frontmatter ของทั้ง .claude/agents/data-researcher.md และ .claude/agents/qa.md คง name, description, tools และบรรทัด mcpServers (ถ้ามี) ของแต่ละไฟล์ไว้เหมือนเดิม ห้ามแก้ body ห้ามใส่ memory ให้ developer หรือ release-manager
```

ผลที่คาดหวัง: ทั้งสองไฟล์มี `memory: project` ใน frontmatter และ `developer.md` **ยังไม่มี** `memory:`

> 📚 **ทำไมสองตัวนี้:** `data-researcher` จำกติกาโดเมน/สแต็ก · `qa` จำวิธีพิสูจน์ ("รีโปรดิวส์ก่อนเขียนรายงาน") — คนละประโยชน์ คนละโน้ต · `developer` ไม่ใส่ เพราะต้องยึดแผนและตัวเลขล่าสุดบนดิสก์ ไม่ใช่ความจำเก่า

### 2. ให้แต่ละตัวจดโน้ตของบทบาทตัวเอง

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
@data-researcher Remember this project note: Registry Insight uses plain Node http and no dependencies. Do not suggest Express unless asked.

@qa Remember this project note: Always reproduce bugs with a real HTTP request before writing docs/QA-REPORT.md. Never trust a developer claim that "it works" without your own reproduction. Do not edit server.js.
```

**เวอร์ชันไทย (ใช้ได้ผลเท่ากัน):**

```text
@data-researcher จดไว้ว่า Registry Insight ใช้ Node http ล้วน ไม่มี dependency ห้ามแนะนำ Express ถ้าไม่ได้ขอ

@qa จดไว้ว่าต้องรีโปรดิวส์บั๊กด้วย HTTP request จริงก่อนเขียน docs/QA-REPORT.md ห้ามเชื่อคำบอกว่า "เวิร์กแล้ว" โดยไม่รีโปรดิวส์เอง ห้ามแก้ server.js
```

### 3. พิสูจน์: ปิดเปิดใหม่แล้วถามสามคำถาม (อย่าใบ้คำตอบ)

`/exit` แล้วเปิด `claude` ใหม่จากโฟลเดอร์เดิม ถามทีละข้อ:

**ก) ตัวที่มี memory ด้านสแต็ก**

```text
@data-researcher ขอแนะนำวิธีทำแอปนี้ให้ดีขึ้นหน่อย
```

ผลที่อยากเห็น: อ้างว่าไม่ใช้ Express / ใช้ Node http ล้วน ถ้าไม่ได้ขอ

**ข) ตัวที่มี memory ด้านวิธีพิสูจน์**

```text
@qa นักพัฒนาบอกว่าแก้ notes แล้วเวิร์ก คุณจะเริ่มตรวจยังไง สั้น ๆ
```

ผลที่อยากเห็น: พูดถึงรีโปรดิวส์ด้วย request จริง / ไม่เชื่อคำบอกก่อนมีหลักฐาน

**ค) ตัวที่ไม่มี memory (ตัวเทียบ)**

```text
@developer ขอแนะนำวิธีทำแอปนี้ให้ดีขึ้นหน่อย
```

ผลที่อยากเห็น: มักไม่พกโน้ตเดียวกับ researcher — จุดสอนคือ **memory ไม่แชร์ข้ามบทบาท** แม้เป็น `project`

> 📚 **รู้เพิ่ม:** ถ้าก) หรือ ข) ไม่อ้างโน้ต ให้จดว่าความจำข้ามเซสชันไม่เกิดในรุ่นที่คุณใช้ แล้วไปต่อได้ — รอบนี้ยังไม่ได้ล็อกผลในสคริปต์ของคอร์ส

## Part B — ฝั่ง OpenCode: ความจำกลางด้วยไฟล์

OpenCode **ไม่มี**ฟิลด์ `memory` ใน frontmatter ของเอเจนต์ (เอกสาร agents ระบุฟิลด์ครบทุกตัว ไม่มี memory) ทางเทียบเท่าคือ**ไฟล์ความจำกลางที่สั่งให้อ่าน** — เขียนครั้งเดียวทั้งทีมใช้ร่วมกัน

### 1. เขียนไฟล์ความจำกลาง

เปิด `opencode` วาง:

```text
เขียน docs/MEMORY.md เป็นภาษาไทย จำห้าข้อนี้
แอปคือ Registry Insight จากข้อมูลจดทะเบียนใหม่ พ.ศ. 2558
ด่านต้องเป็น 6/6 ก่อนบอกว่าเสร็จ
ห้ามแก้ scripts/quality-gate.js
ห้ามพิมพ์ค่าที่ขึ้นต้นด้วย sk-
โน้ตบนเครื่องเขียนไฟล์ได้ โน้ตบน Vercel เป็นอ่านอย่างเดียว
ห้ามใส่คีย์ลงไฟล์นี้
```

ตรวจด้วยตาว่าไฟล์ไม่มีค่าที่ขึ้นต้น `sk-` แม้เป็นตัวอย่าง

### 2. พิสูจน์: ปิดโปรแกรมสนิท เปิดใหม่ แล้วถามโดยไม่ใบ้

ปิด OpenCode ให้สนิท เปิดใหม่ แล้ววาง:

```text
อ่าน docs/MEMORY.md แล้วบอกฉันว่าก่อนส่งของต้องเห็นด่านแบบไหน และโน้ตบน Vercel ทำไมเขียนไฟล์ไม่ได้
```

คำตอบต้องมาจากไฟล์ ไม่ใช่จากการเดาทับ ให้มันอ้างข้อหรือบรรทัดได้ยิ่งดี

### 3. ผูกความจำเข้าตัวตน — ทางเทียบเท่าของ `memory: project`

วางต่อให้เพิ่มบรรทัดในไฟล์บทบาท (แล้วปิดเปิดใหม่ก่อนใช้จริง):

```text
แก้ .opencode/agents/planner.md และ .opencode/agents/developer.md โดยเพิ่มกฎหนึ่งบรรทัดในเนื้อไฟล์ว่า "ก่อนตอบงานใด ให้อ่าน docs/MEMORY.md ก่อนเสมอ" อย่าแก้อย่างอื่นในไฟล์
```

แล้วถาม planner ในรอบใหม่เรื่องงานใดก็ได้ — ต้องเห็นมันอ้าง `docs/MEMORY.md` ก่อนตอบ ต่างจากฝั่ง Claude ตรงที่ต้อง**สั่งให้อ่านเอง** เพราะไม่มีฟิลด์ memory ให้ระบบโหลดให้อัตโนมัติ

### 4. ปิดท้ายทุกรอบด้วยพิธีจด — ครึ่งที่ OpenCode ไม่มีอัตโนมัติ

สังเกตความอสมมาตร: ฝั่ง Claude ระบบ**อ่านให้เอง** แต่การจดก็ต้องสั่ง ("Remember this…") ฝั่ง OpenCode ทั้งอ่านและจด**ต้องสั่ง** และไม่มี hook "จบ session" ให้ plugin อัตโนมัติแบบที่เอกสารรับรอง วิธีที่ใช้ได้จริงคือพิธีปิดรอบหนึ่งบรรทัด — ก่อน `/exit` ทุกครั้ง วาง:

```text
สรุปข้อตกลงใหม่ที่เกิดขึ้นวันนี้ที่ยังไม่อยู่ใน docs/MEMORY.md แล้วเขียนเพิ่มเป็นข้อ ๆ สั้น ๆ ถ้าไม่มีอะไรใหม่ ให้บอกว่าไม่มี ห้ามแต่งข้อ
```

ทำเป็นนิสัยเดียวกันท้ายทุก session แล้วไฟล์กลางจะไม่ค้าง — ถ้ามีคนสนใจระดับ plugin จริง ๆ OpenCode มี `compaction` hook กับ `ctx.experimental.generate.text` ให้ DIY ได้ แต่ยัง experimental และไม่มี API เขียนไฟล์ตรง ๆ — เกินขอบเขตห้องนี้

## ผ่านเมื่อ

**ฝั่ง Claude:**
- `data-researcher.md` และ `qa.md` มี `memory: project` ส่วน `developer.md` **ไม่มี**
- เปิดเซสชันใหม่หลังจดโน้ตแล้วถามครบสามข้อ และจดผลว่าใครอ้างโน้ตของตัวเองได้บ้าง

**ฝั่ง OpenCode:**
- มี `docs/MEMORY.md` ครบห้าข้อ ไม่มีคีย์ลงไฟล์
- ปิดโปรแกรมสนิทแล้วเปิดใหม่จริง คำตอบอ้างข้อตกลงจากไฟล์ได้ครบทั้ง 6/6 และโน้ตอ่านอย่างเดียวบน Vercel
- วางพิธีจดท้ายรอบแล้ว (ข้อใหม่เข้าไฟล์ / ไม่มีใหม่ต้องบอกว่าไม่มี)

## ถ้าติดขัด

| อาการ | สาเหตุ | แก้ |
|---|---|---|
| เซสชัน Claude ใหม่ไม่จำ | ยังไม่รีสตาร์ท หรือเปิดคนละโฟลเดอร์ | เปิดจากโฟลเดอร์แอปแล้วเรียกด้วย `@` ชัด ๆ |
| รอบใหม่ opencode ยังตอบถูกทั้งที่ไม่มีไฟล์ | ปิดไม่สนิท session เดิมยังอยู่ | ปิดหน้าต่างจริง เช็กว่าไม่มี `--continue` แล้วเปิดใหม่ |
| รอบใหม่ opencode ไม่จำ | ไม่ได้สั่งให้อ่านไฟล์ก่อนตอบ | คำถามต้องขึ้นต้นว่า "อ่าน docs/MEMORY.md แล้ว…" |
| รอบใหม่ opencode ไม่อ่าน MEMORY.md หลังผูกตัวตน | ยังไม่ปิดเปิดใหม่หลังแก้ไฟล์บทบาท | ไฟล์บทบาทโหลดตอนเปิดรอบเท่านั้น |
| เขียน MEMORY.md ใส่คีย์ | เข้าใจผิดว่าคือที่เก็บค่า | ลบทันที ไฟล์นี้ถูก commit คนถัดไปอ่าน |
| ทั้ง researcher และ developer ตอบคล้ายกัน (ฝั่ง Claude) | โน้ตไปโผล่ใน CLAUDE.md หรือถามไม่ระบุ `@` | เรียกด้วย `@` ชัด · เทียบเฉพาะหลังรีสตาร์ท |

## ถ้าตามไม่ทัน

```bash
รันจาก repo บทเรียน (build-ai-multi-agent-hybrid) ไม่ใช่จากโฟลเดอร์แอป:
node scripts/catch-up.js w5
```

ชุดนี้มีทั้งเช็กลิสต์และ `docs/MEMORY.md` ให้อ่านไฟล์ความจำแล้วถามรอบใหม่เองหนึ่งครั้ง ฝั่ง Claude ทำตามขั้น A ได้ภายในห้านาที (ไม่มี catch-up — เขียนสี่บรรทัดเองได้)

## ต่อยอด

เพิ่มข้อที่หกลง `docs/MEMORY.md` จากสิ่งที่ห้องเจอเองวันนี้ แล้วทดสอบเรียกข้ามรอบซ้ำ ฝั่ง Claude ลองจดโน้ตใหม่ให้ qa แล้วดูว่าโน้ตเก่าถูกแทนหรือรวมกัน

## รู้เพิ่ม

สองกลไกสองปรัชญา และไม่สมมาตร: ฝั่ง Claude ระบบ**อ่านให้เอง** (จดเมื่อสั่งจด) ฝั่ง OpenCode ทั้งอ่านและจด**ต้องสั่ง** (อ่าน — ผูกในไฟล์บทบาทหรือสั่งตอนถาม · จด — พิธีปิดรอบขั้น 4) ความจำทั้งคู่ไม่ใช่ที่เก็บคีย์ และถ้าวันหนึ่ง OpenCode ออกฟีเจอร์ memory ในตัว ให้กลับมาอัปเดตโมดูลนี้ตามเอกสาร agents อีกครั้ง
