# Module 10 — ความจำข้ามรอบ: สองกลไก สองฝั่ง

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ทุกเช้าที่เปิดผู้ช่วยรอบใหม่ มันลืมทุกอย่าง ยกเว้นสิ่งที่เราเขียนลงไฟล์ คอร์สนี้สอนความจำสองกลไกที่ปรัชญาต่างกัน: ฝั่ง **Claude Code** ใช้ `memory: project` ใน frontmatter ของเอเจนต์ — ระบบโหลดโน้ตของแต่ละบทบาทให้**เองอัตโนมัติ** และความจำ**ไม่แชร์ข้ามบทบาท** ฝั่ง **OpenCode** ไม่มีฟิลด์ memory (เอกสาร agents ระบุฟิลด์ครบทุกตัว ไม่มีตัวนี้) จึงใช้**ไฟล์ความจำกลาง** `docs/MEMORY.md` ที่ทั้งทีมอ่านร่วมกันโดยต้องสั่งให้อ่าน

ทั้งสองแบบต้องผ่านการพิสูจน์เดียวกัน: ปิดโปรแกรมสนิท เปิดใหม่ แล้วถาม**โดยไม่ใบ้** — คำตอบที่ดีต้องมาจากไฟล์ ไม่ใช่การเดาทับ และอสมมาตรที่ต้องรู้: ฝั่ง Claude ระบบ**อ่านให้เอง** ฝั่ง OpenCode ทั้งอ่านและจด**ต้องสั่ง** — จึงมี "พิธีจดท้ายรอบ" หนึ่งบรรทัดเป็นนิสัยปิดท้ายทุก session

## Concept / เนื้อหา

### Part A — ฝั่ง Claude: ความจำรายบทบาท (จากเครื่องทดสอบ)

ใส่ `memory: project` ให้ `data-researcher` + `qa` แล้วให้แต่ละตัวจดโน้ตของบทบาทตัวเอง:

| ตัว | โน้ตที่จด | ตัวเทียบ |
|---|---|---|
| `data-researcher` | "ใช้ Node http ล้วน ไม่มี dependency ห้ามแนะนำ Express ถ้าไม่ได้ขอ" | `developer` **ไม่มี** memory — มักไม่พกโน้ตเดียวกัน |
| `qa` | "รีโปรดิวส์ด้วย request จริงก่อนเขียนรายงาน ห้ามเชื่อคำว่าเวิร์ก" | |

จุดสอน: memory ไม่แชร์ข้ามบทบาทแม้เป็น `project` — ตัวที่ไม่ใส่คือตัวเทียบให้เห็นความต่าง

### Part B — ฝั่ง OpenCode: ไฟล์กลางที่ต้องสั่งอ่าน

`docs/MEMORY.md` เขียนครั้งเดียวทั้งทีมใช้ร่วม (ห้าข้อ: ตัวแอป, ด่าน 6/6, ห้ามแก้ด่าน, ห้ามพิมพ์ `sk-`, โน้ตสองโลก) รอบทดสอบจริงปิดโปรแกรมสนิทเปิดใหม่แล้วถาม — มันตอบกลับมาอ้างเลขบรรทัดของ `docs/MEMORY.md` ("ด่าน 6/6 ก่อนออกจาก สายสั้น (บรรทัด 23)") — หลักฐานว่าอ่านไฟล์จริง ไม่ใช่เดา

และเพราะไม่มีฟิลด์ memory ให้ระบบโหลดเอง ทางทำให้ตัวตนจำคือ**เพิ่มกฎหนึ่งบรรทัดในไฟล์บทบาท**: "ก่อนตอบงานใด ให้อ่าน docs/MEMORY.md ก่อนเสมอ" — สั่งอ่านเองคือราคาของกลไกไฟล์กลาง

### Part C — เทียบสองกลไก

| | Claude `memory: project` | OpenCode `docs/MEMORY.md` |
|---|---|---|
| ขอบเขต | รายบทบาท ไม่แชร์กัน | กลางทั้งทีม |
| อ่าน | อัตโนมัติทุกรอบ | ต้องสั่งอ่าน (หรือผูกในไฟล์บทบาท) |
| เขียน | ตัวเองเขียนเมื่อสั่งจด ("Remember this…") | คุณสั่งเขียนท้ายรอบ — **ไม่มีอัตโนมัติ** (plugin DIY ยัง experimental) |
| เหมาะกับ | กติกาประจำตัวของแต่ละหน้าที่ | ข้อตกลงร่วมของทั้งทีม |
| ราคา | ความจำโหลดทุกรอบแม้ไม่ใช้ | ต้องจำว่ามีไฟล์นี้อยู่ + พิธีจดท้ายรอบ |

## ลำดับในห้อง (ภาพรวม)

1. Part A: ใส่ `memory: project` ให้ data-researcher + qa → จดโน้ตรายบทบาท → ปิดเปิดใหม่ → ถามสามคำถาม (researcher / qa / developer ตัวเทียบ)
2. Part B: สั่ง opencode เขียน `docs/MEMORY.md` → ปิดสนิทเปิดใหม่ → ถามโดยไม่ใบ้ → ต้องอ้างไฟล์
3. ผูก MEMORY.md เข้าตัวตน opencode ด้วยกฎหนึ่งบรรทัด → ทดสอบซ้ำ

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 30 นาที ถ้าห้องช้าให้วิทยากรสาธิตฝั่งใดฝั่งหนึ่งได้

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **ความจำ Claude ไม่แชร์ข้ามบทบาท** — คาดหวังให้ developer พกโน้ตของ researcher คือเข้าใจผิด ใช้เป็นตัวเทียบแทน
- **ความจำ OpenCode ต้องสั่งอ่าน** — คำถามต้องขึ้นต้น "อ่าน docs/MEMORY.md แล้ว…" ไม่งั้นมันตอบจาก session หรือเดา
- **ทดสอบโดยยังไม่ปิดโปรแกรมสนิท** — session เก่ายังอยู่ คำตอบมาจากความจำใน session ไม่ใช่ไฟล์ ต้องเห็นพรอมต์ใหม่จริงก่อน
- **ใส่คีย์ในไฟล์ความจำ** — ไฟล์ถูก commit ผิดกติกาและผิดจุดประสงค์
- **Z.AI overload ถาวร (ฝั่ง opencode)** — โดน "temporarily overloaded" ติดต่อกันสองรอบให้พักสามนาทีแล้วส่งซ้ำ รอบสามผ่าน (34 วินาที) — คนละรูปแบบกับ "Retrying... attempt N" ที่รอได้
- **เขียนความจำเป็นเรียงความ** — ยิ่งยาวยิ่งไม่ถูกอ่าน ห้าข้อสั้นพอแล้ว

## Quick check / ทบทวน

- `memory: project` กับ `docs/MEMORY.md` ต่างกันตรงไหน? — อันแรกรายบทบาทโหลดเอง อันหลังกลางทั้งทีมต้องสั่งอ่าน
- `CLAUDE.md` กับความจำพวกนี้ต่างกันไหม? — กติกาตายตัวของแอปโหลดอัตโนมัติทุกตัว ส่วนความจำคือข้อตกลงที่เพิ่มขึ้นระหว่างทาง
- รู้ได้ยังไงว่าโมเดลอ่านไฟล์จริง ไม่ใช่เดา? — ให้อ้างที่มา (บรรทัด/ข้อ) แล้วไปดูไฟล์ว่าตรง
- โน้ต Vercel ทำไมอ่านอย่างเดียว? — ดิสก์ของฟังก์ชันไม่รับประกันอยู่ถึงคำขอถัดไป ข้อมูลจะหายเอง
