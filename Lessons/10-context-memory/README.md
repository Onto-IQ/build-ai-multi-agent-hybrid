# Module 10 — ความจำข้ามรอบ

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ทุกเช้าที่เปิดผู้ช่วยรอบใหม่ มันลืมทุกอย่าง ยกเว้นสิ่งที่เราเขียนลงไฟล์ `CLAUDE.md`/`AGENTS.md` โหลดอัตโนมัติ แต่ข้อตกลงที่เพิ่มเกิดขึ้นระหว่างทาง (งานวันนี้จบด้วยด่าน 6/6 โน้ตสองโลกต่างกัน) ต้องมีที่อยู่ของตัวเอง ไฟล์นั้นคือ `docs/MEMORY.md` — ข้อตกลงของห้องเขียนเป็นภาษาไทย สั้น อ่านจบในหนึ่งหน้า

จุดสำคัญที่โมดูลนี้พิสูจน์: **คำตอบต้องมาจากไฟล์ ไม่ใช่การเดาทับ** ทดสอบด้วยการปิดโปรแกรมสนิท เปิดใหม่ แล้วถามโดยไม่แปะห้าข้อซ้ำ — รอบทดสอบจริงตอบกลับมาอ้างเลขบรรทัดของ `docs/MEMORY.md` ("ด่าน 6/6 ก่อนออกจาก สายสั้น (บรรทัด 23)") และอธิบายเหตุผลของโน้ต Vercel ได้ถูกต้อง นั่นคือหลักฐานว่าความจำอยู่ที่ไฟล์จริง

## Concept / เนื้อหา

### Part A — ห้าข้อที่ต้องจำ

| ข้อ | ใจความ |
|---|---|
| 1 | แอปคือ Registry Insight จากข้อมูลจดทะเบียนใหม่ พ.ศ. 2558 |
| 2 | ด่านต้องเป็น 6/6 ก่อนบอกว่าเสร็จ |
| 3 | ห้ามแก้ `scripts/quality-gate.js` |
| 4 | ห้ามพิมพ์ค่าที่ขึ้นต้นด้วย `sk-` |
| 5 | โน้ตบนเครื่องเขียนไฟล์ได้ โน้ตบน Vercel เป็นอ่านอย่างเดียว |

ไฟล์จริงที่ได้เพิ่มข้อที่มาจากกติกาโปรเจกต์ด้วย (ทางขึ้น Vercel คือ `api/*.js` ไม่ใช่ server.js บนพอร์ต, ห้าม `git push` เอง, ห้ามตั้งคีย์บน Vercel) — เหมือนและเกินตามที่บริบทมันเห็นมา

### Part B — ทำไมความจำไม่ใช่ที่เก็บคีย์

ไฟล์ความจำถูก commit และถูกอ่านทุกรอบ ถ้าเผลอใส่ค่าคีย์ลงไป คีย์จะเดินทางไปกับทุกสำเนาของ repo กฎ "ห้ามพิมพ์ค่า sk-" จึงมีทั้งเหตุผลด้านความปลอดภัยและด้านวินัยการเขียนไฟล์

### Part C — เพดานของความจำ

ไฟล์นี้ไม่ใช่ประวัติศาสตร์ทั้งหมดของโปรเจกต์ มันคือ**ข้อตกลงที่ต้องอยู่รอดข้ามรอบ**เท่านั้น ของที่เก่ากว่า (รายงานสำรวจ รายงาน QA) อยู่ในไฟล์ของตัวเองอยู่แล้ว ความจำที่ยาวเกินหนึ่งหน้าจะไม่มีใครอ่าน รวมทั้งโมเดล

## ลำดับในห้อง (ภาพรวม)

1. สั่ง opencode เขียน `docs/MEMORY.md` จากห้าข้อ
2. ปิดโปรแกรมสนิท → เปิดใหม่ → ถามสองคำถามโดยไม่แปะห้าข้อ
3. คำตอบต้องมีที่มาจากไฟล์ (ระบุบรรทัดหรือข้อ)

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 20 นาที ถ้าห้องช้าให้วิทยากรสาธิตได้

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **Z.AI overload ถาวร** — รอบทดสอบโดน "Error: The service may be temporarily overloaded" ติดต่อกันสองรอบโดยไม่ retry ให้พักสามนาทีแล้วส่งคำถามซ้ำ รอบสามผ่าน (34 วินาที) — คนละรูปแบบกับ "Retrying... attempt N" ที่รอได้
- **เขียนความจำเป็นเรียงความ** — ยิ่งยาวยิ่งไม่ถูกอ่าน ห้าข้อสั้นพอแล้ว
- **ใส่คีย์ในไฟล์ความจำ** — ผิดกติกาและผิดจุดประสงค์ ไฟล์นี้ถูก commit
- **ทดสอบโดยยังไม่ปิดโปรแกรมสนิท** — ถ้า session เก่ายังอยู่ คำตอบจะมาจากความจำใน session ไม่ใช่จากไฟล์ ต้องเห็นพรอมต์ PowerShell ใหม่จริงก่อน

## Quick check / ทบทวน

- `CLAUDE.md` กับ `docs/MEMORY.md` ต่างกันตรงไหน? — อันแรกคือกติกาตายตัวของแอปโหลดอัตโนมัติ อันหลังคือข้อตกลงที่เพิ่มขึ้นระหว่างทางและต้องสั่งอ่านเมื่อใช้
- รู้ได้ยังไงว่าโมเดลอ่านไฟล์จริง ไม่ใช่เดา? — ให้มันอ้างที่มา (บรรทัด/ข้อ) แล้วไปดูไฟล์ว่าตรง
- โน้ต Vercel ทำไมอ่านอย่างเดียว? — ดิสก์ของฟังก์ชันไม่รับประกันอยู่ถึงคำขอถัดไป ข้อมูลจะหายเอง

## Go deeper

- เพิ่มข้อที่หกลง `docs/MEMORY.md` จากสิ่งที่ห้องเจอเองวันนี้ แล้วทดสอบเรียกข้ามรอบซ้ำ
- เปิด `docs/MEMORY.md` เทียบกับ `CLAUDE.md` แล้วหาข้อที่ซ้ำกัน — คุยว่าควรซ้ำหรือไม่ (เฉลย: ข้อตายตัวซ้ำได้ เพราะไฟล์ไหนถูกอ่านก่อนก็คุ้ม)
- ลองถามสิ่งที่ไม่ได้เขียนในไฟล์ แล้วดูว่ามันเดาหรือปฏิเสธ (คนที่ดีจะบอกว่าไม่มีข้อมูล)
