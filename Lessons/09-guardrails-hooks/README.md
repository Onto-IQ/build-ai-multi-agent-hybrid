# Module 09 — กันคำสั่งอันตราย และกันงบบาน

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ตอนนี้ผู้ช่วยทำงานได้จริงแล้ว (ด่าน 6/6) ความเสี่ยงจึงเปลี่ยนจาก "ทำงานไม่ได้" เป็น "ทำเกินขอบเขต" — ลบข้อมูลทิ้ง รันคำสั่งอันตราย หรือกินงบโมเดลบานปลาย โมดูลนี้วางรั้วสองชนิดที่กลไกต่างกัน: **hook** คือสคริปต์ที่ Claude Code เรียกทุกครั้งก่อนทำ (PreToolUse) และตอนจบงาน (TaskCompleted) — มัน exit 2 ก็หยุดทันที, ส่วน **cost-gate** คือสคริปต์ตัดสินจากไฟล์บันทึกการใช้งาน เพดานของห้อง: ไม่เกิน 2 ดอลลาร์ และไม่เกิน 20,000 output tokens ต่อรอบที่บันทึก

จุดที่ต้องเข้าใจคือรั้วพวกนี้กัน**อุบัติเหตุ** ไม่กันคนที่ตั้งใจปิดรั้วเอง (ใครแก้ settings.json ก็เลิกรั้วได้) แต่โลกจริงส่วนใหญ่เป็นอุบัติเหตุจากโมเดลเดาผิด รั้วจึงคุ้มค่า

## Concept / เนื้อหา

### Part A — สามชิ้นที่ได้จากโมดูลนี้ (จากเครื่องทดสอบจริง)

| ชิ้น | กลไก | ผลทดสอบจริง |
|---|---|---|
| `.claude/hooks/block-dangerous-bash.js` | PreToolUse: อ่าน JSON จาก stdin, exit 2 เมื่อเห็น `rm -rf` / `taskkill` / `Remove-Item -Recurse` / pipe เข้า sh; ผ่าน `node server.js` กับตัวด่าน | สั่ง `rm -rf data` → ถูกบล็อก, `data/raw/dbd-2558.parquet` ยังอยู่ครบ |
| `.claude/hooks/task-completed-gate.js` | TaskCompleted: exit 2 ถ้า `qualityGatePassed` ไม่ใช่ true | ปิดงานต้องพาด่านติดมาด้วย |
| `scripts/cost-gate.js` | อ่านไฟล์ JSON จากอาร์กิวเมนต์, exit 2 เกิน 2 ดอลลาร์หรือ 20,000 output tokens | `under-budget` exit 0 · `over-budget` (3.5) exit 2 · `over-tokens` (25,000) exit 2 |

ทั้งหมดผสานใน `.claude/settings.json` โดย deny สี่กฎจาก Module 04 (ด่าน + push) ยังอยู่ครบ

### Part B — ฝั่ง OpenCode ไม่ทำซ้ำ

OpenCode ไม่มีระบบ hook แบบเดียวกัน จึงใช้เส้นสิทธิ์จาก Module 04 เป็นรั้ว (deny แก้ด่าน + deny push) รอบทดสอบสั่งให้มันอ่าน `opencode.json` แล้วยืนยัน — มันตอบกลับมาเป็นลิสต์ 3 กฎ deny พร้อมสรุป "ยังห้ามอยู่" ภารกิจคือ**ตรวจว่ารั้วยังยืนอยู่ ไม่ใช่สร้างใหม่**

### Part C — เพดานงบคือเกณฑ์ฝึก

ไฟล์ [scripts/gate-cost.md](../../scripts/gate-cost.md) นิยามเพดานห้อง: ≤ 2 USD, ≤ 20,000 output tokens ต่อรองเรียนบันทึก อธิบายกับห้องว่านี่ไม่ใช่ใบเสร็จจริงจาก Anthropic แต่เป็น**เกณฑ์ที่ตกลงกันไว้เพื่อฝึกอ่านและบังคับงบ** — พฤตินิยมเดียวกับด่านคุณภาพ

## ลำดับในห้อง (ภาพรวม)

1. Claude: สั่งสร้างสอง hook + ผสาน settings.json (คง deny เดิม) → ทดลอง `rm -rf data` ต้องไม่หาย → gate ยัง 6/6
2. ก็อป fixtures จาก `solutions/w7/fixtures/` → สั่งสร้าง `scripts/cost-gate.js` → ทดสอบสามไฟล์ 0/2/2
3. OpenCode: ยืนยันเส้นสิทธิ์จาก Module 04 ยังครบ

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **hook บล็อกเกินขอบเขต** — ถ้าบล็อกคำที่กว้างเกิน (เช่นทุกคำสั่งที่มีคำว่า remove) งานปกติจะโดนด้วย ทดสอบทั้งฝั่งต้องบล็อกและฝั่งต้องผ่านเสมอ
- **cost-gate เขียนด้วยเงื่อนไขชลูด** — บังคับพิมพ์ PASS/FAIL ให้ชัด + exit code ตรง เพราะจะถูกนำไปผูกกับ CI ต่อ
- **คลิปบอร์ดเพี้ยนระหว่างรอ** — ระบบอื่นบนเครื่องอาจเขียนทับคลิปบอร์ดขณะรอโมเดล (เคสจริง: ข้อความกลายเป็น "ลบนี้ Phase 0" ทำให้ opencode เริ่มงานสำรวจใหญ่) — ตั้งคลิปบอร์ดแล้วดูช่องพิมพ์ใน TUI ก่อนกด Enter ทุกครั้ง ถ้าข้อความผิดให้ Esc ทันที
- **โมเดล overload วน retry** — เกือบทุกคำสั่งรอบนี้โดน attempt 2–5 ให้รอ ผลไม่เปลี่ยน
- **อย่าให้ hook เรียกเน็ต** — ทุกคำสั่งทุกครั้งจะช้าลงและพังตอนออฟไลน์

## Quick check / ทบทวน

- PreToolUse กับ TaskCompleted ต่างกันยังไง? — หนึ่งกั้นก่อนทำ (คำสั่งอันตราย) หนึ่งกั้นก่อนปิดงาน (งานจบแต่ด่านยังแดง = ไม่นับเสร็จ)
- ทำไมฝั่ง OpenCode ไม่สร้าง hook ซ้ำ? — กลไกต่างกัน และรั้วที่มีอยู่ (opencode.json) ครอบเรื่องอันตรายที่เกี่ยวกับสายงานของมันอยู่แล้ว ซ้ำซ้อนแต่ดูแลสองที่
- `rm -rf data` โดนบล็อกแล้ว จะรันจริงได้ไหมเมื่อจำเป็น? — ได้ โดยแก้รายการ allow ใน hook หลังคิดแล้ว — นั่นคือข้อแตกต่างจากกฎสากล: รั้วเป็นของทีม แก้ได้ตามกระบวนการ ไม่ใช่ข้ามหลังบ้าน
