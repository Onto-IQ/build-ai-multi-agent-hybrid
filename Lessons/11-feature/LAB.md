# Module 11 — ฟีเจอร์ของตัวเอง

**ทำไปเพื่ออะไร:** ลองเอาวิธีสั่งทีมไปใช้กับเรื่องที่ตัวเองสนใจ ไม่ใช่แค่ทำตามสคริปต์

**แล็บนี้ย่อได้** ถ้าห้องช้า ให้เหลือ 30 นาที หรือรวม 2–3 คนทำชิ้นเดียว

| เวลา | เครื่องมือ |
|---|---|
| **60 นาที** ถ้าย่อเหลือ **30 นาที** | เลือก Claude Code หรือ OpenCode เอง |

ทำในโฟลเดอร์แอป

## ก่อนเริ่ม

ด่านเป็น 6/6 เลือกฟีเจอร์เล็กหนึ่งชิ้นที่อ่านจากข้อมูลชุดนี้ได้ เช่น จังหวัดที่ทุนสูงสุดบนหน้าเว็บ, ช่องค้นชื่อบริษัท, หรือยอดแยกภาค ห้ามเปลี่ยนตัวเลขหลักของด่าน

## แบบฝึกหัด

### 1. เขียนหนึ่งย่อหน้าก่อนสั่ง

ลง `docs/MY-FEATURE.md` ด้วยภาษาคน:

- ผู้ใช้จะเห็นอะไรเพิ่ม
- ไฟล์ไหนที่อนุญาตให้แตะ
- อะไรที่ห้ามแตะ (`scripts/quality-gate.js`, คีย์, ยอด 16,772 / 45,341,868,784)

### 2. สั่งผู้ช่วยสองจังหวะ

จังหวะวางแผน ห้ามแก้โค้ด จังหวะลงมือทำตามไฟล์แผนเท่านั้น ใช้เครื่องมือที่เลือก วาง:

```text
อ่าน docs/MY-FEATURE.md
รอบนี้เขียนได้แค่ docs/MY-FEATURE-TASKS.md เป็นลิสต์ไม่เกิน 5 ข้อ
ห้ามแก้โค้ดในรอบนี้
```

เปิดไฟล์แผนด้วยตา แล้วค่อยวาง:

```text
ทำตาม docs/MY-FEATURE-TASKS.md เท่านั้น
ห้ามแก้ scripts/quality-gate.js
ห้ามพิมพ์ค่า sk-
เสร็จแล้วรัน npm run gate ถ้าไม่ผ่านให้หยุด รายงาน exit code จริง
```

### 3. เปิดหน้าเว็บเอง

`npm start` แล้วคลิกดูว่าฟีเจอร์ปรากฏจริง ไม่ใช่แค่มีคำว่าเสร็จในแชท

## ผ่านเมื่อ

- มีฟีเจอร์หนึ่งชิ้นที่เปิดดูได้
- `npm run gate` ยังเป็น 6/6
- `docs/MY-FEATURE.md` บอกว่าใครทำอะไรส่งต่อให้ใครอย่างน้อยสองจังหวะ

ถ้าย่อเวลา ผ่านเมื่อมีไฟล์แผนและหน้าเว็บเปลี่ยนหนึ่งจุด โดยด่านยังเขียว ไม่ต้องครบห้าข้อในแผน

## ถ้าตามไม่ทัน

แล็บนี้ไม่มีของสำเร็จรูปให้ก็อป เกณฑ์อยู่ที่ `solutions/w8/FEATURE-CRITERIA.md` ใน repo บทเรียน อ่านเกณฑ์แล้วทำชิ้นที่เล็กที่สุด

```bash
node scripts/catch-up.js w8
```

คำสั่งนี้จะไม่เขียนทับแอป
