## ก่อนเริ่ม

ด่านเป็น 6/6 เลือกฟีเจอร์หนึ่งชิ้นจากเมนู (หรือของเองในกรอบเดียวกัน) ห้ามเปลี่ยนตัวเลขหลักของด่าน

**เมนู 5 แบบ:**

| รหัส | ฟีเจอร์ |
|---|---|
| **A** ★ | ตารางจังหวัดโต้ตอบได้: ค้นตามชื่อจังหวัด เรียงคอลัมน์ เลือก 10/20/ทั้งหมด |
| B | Top ทุนสูงสุด สลับ Top 10 / Top 20 |
| C | การ์ด/แท่งเทียบรายเดือน ม.ค./ก.พ./มิ.ย. จำนวนกิจการ+ทุน |
| D | ช่องค้นคำในวัตถุประสงค์ โชว์รายชื่อกิจการที่ตรง |
| E | ปุ่มดาวน์โหลด CSV ของสรุปจังหวัด/ภาคที่เห็นบนหน้า |

★ A แนะนำถ้าจะต่อ Capstone บทที่ 12 แบบสเปกตารางจังหวัด

**เกณฑ์กำกับทุกข้อก่อนเรียกว่าเสร็จ:** (1) อยู่ใน build ที่จะขึ้น Vercel ใน Module 13 ได้จริง (2) gate ยัง exit 0 (3) ผ่านอย่างน้อย 2 จังหวะแบบมี handoff บนไฟล์ ไม่ใช่แชทล้วน (4) ไม่แตะ `scripts/quality-gate.js`, ไม่พิมพ์ค่า `sk-`, ไม่เพิ่ม dependency

## แบบฝึกหัด

### 1. เขียนหนึ่งย่อหน้าก่อนสั่ง

ลง `docs/MY-FEATURE.md` ด้วยภาษาคน:

- ผู้ใช้จะเห็นอะไรเพิ่ม
- ไฟล์ไหนที่อนุญาตให้แตะ
- อะไรที่ห้ามแตะ (`scripts/quality-gate.js`, คีย์, ยอด 16,772 / 45,341,868,784)

### 2. สั่งผู้ช่วยสองจังหวะ

จังหวะวางแผน ห้ามแก้โค้ด จังหวะลงมือทำตามไฟล์แผนเท่านั้น ใช้เครื่องมือที่เลือก วาง (เลือกอย่างใดอย่างหนึ่ง):

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
Read docs/MY-FEATURE.md.
This round you may write only docs/MY-FEATURE-TASKS.md — a list of at most 5 items.
Do not edit code in this round.
```

**เวอร์ชันไทย (ใช้ได้ผลเท่ากัน):**

```text
อ่าน docs/MY-FEATURE.md
รอบนี้เขียนได้แค่ docs/MY-FEATURE-TASKS.md เป็นลิสต์ไม่เกิน 5 ข้อ
ห้ามแก้โค้ดในรอบนี้
```

เปิดไฟล์แผนด้วยตา แล้วค่อยวาง (เลือกอย่างใดอย่างหนึ่ง):

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
Follow docs/MY-FEATURE-TASKS.md only.
Do not edit scripts/quality-gate.js.
Never print any sk- value.
When done, run npm run gate; if it fails, stop and report the real exit code.
```

**เวอร์ชันไทย (ใช้ได้ผลเท่ากัน):**

```text
ทำตาม docs/MY-FEATURE-TASKS.md เท่านั้น
ห้ามแก้ scripts/quality-gate.js
ห้ามพิมพ์ค่า sk-
เสร็จแล้วรัน npm run gate ถ้าไม่ผ่านให้หยุด รายงาน exit code จริง
```

### 3. ให้ qa ตรวจรับ แล้วเปิดหน้าเว็บเอง

วางต่อ (เลือกอย่างใดอย่างหนึ่ง):

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
Acceptance-check the new feature: <your feature sentence>. Verify the web page really works, the gate is still 6/6, and nothing prints sk-, then append the result to docs/QA-REPORT.md as a new section naming the feature code you chose.
```

**เวอร์ชันไทย (ใช้ได้ผลเท่ากัน):**

```text
ตรวจรับ feature ใหม่: <ประโยคฟีเจอร์ของคุณ> ตรวจว่าหน้าเว็บทำงานจริง gate ยัง 6/6 และไม่มีอะไรพิมพ์ sk- แล้ว append ผลเข้า docs/QA-REPORT.md เป็นหัวข้อใหม่ ระบุรหัสฟีเจอร์ที่เลือก
```

จากนั้น `npm start` แล้วคลิกดูว่าฟีเจอร์ปรากฏจริง ไม่ใช่แค่มีคำว่าเสร็จในแชท

## ผ่านเมื่อ

- มีฟีเจอร์หนึ่งชิ้นที่เปิดดูได้จริงบนหน้าเว็บ
- `npm run gate` ยังเป็น 6/6 exit 0
- ผ่านอย่างน้อยสองจังหวะมี handoff บนไฟล์ (แผนไฟล์หนึ่ง งานตามแผนหนึ่ง)
- `docs/QA-REPORT.md` มีหัวข้อตรวจรับฟีเจอร์ของคุณ
- `docs/MY-FEATURE.md` บอกว่าใครทำอะไรส่งต่อให้ใครอย่างน้อยสองจังหวะ

ถ้าย่อเวลา ผ่านเมื่อมีไฟล์แผนและหน้าเว็บเปลี่ยนหนึ่งจุด โดยด่านยังเขียว ไม่ต้องครบห้าข้อในแผน
