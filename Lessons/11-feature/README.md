# Module 11 — ฟีเจอร์ของตัวเอง

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

สิบโมดูลที่ผ่านมา ทุกคำสั่งมีสคริปต์กำกับ โมดูลนี้คือการสอบย่อย: หยิบวิธีสั่งทีม (บรีฟก่อน → แผนก่อนแก้ → ด่านตัดสิน) ไปใช้กับเรื่องที่**ตัวเอง**เลือก เกณฑ์กำกับเหมือนเดิม — ฟีเจอร์ใหญ่แค่ไหนก็ได้ แต่ด่านต้องยังผ่าน 6/6 และยอดหลัก 16,772 / 45,341,868,784 ห้ามเพี้ยน ฟีเจอร์ที่ทำให้ตัวเลขหลักเปลี่ยนคือฟีเจอร์ที่ทำผิด

## Concept / เนื้อหา

### Part A — ฟีเจอร์ตัวอย่างที่รันจริง (ชิ้นเล็กสุดที่เห็นของจริง)

เลือก "จังหวัดที่ทุนสูงสุด 5 อันดับ" — ผ่านสองจังหวะบน Claude Code:

| จังหวะ | คำสั่ง | ผล |
|---|---|---|
| แผน | "อ่าน docs/MY-FEATURE.md รอบนี้เขียนได้แค่ docs/MY-FEATURE-TASKS.md ลิสต์ไม่เกิน 5 ข้อ ห้ามแก้โค้ด" | แผน 5 ข้อที่ค้นพบของเดิมที่ใช้ได้: `analyze()` คำนวณ `stats.byProvince` ไว้แล้ว — endpoint ใหม่แค่จัดอันดับและเสิร์ฟ |
| ทำ | "ทำตาม docs/MY-FEATURE-TASKS.md เท่านั้น ... รัน gate รายงาน exit code จริง" | `GET /api/provinces/top` + การ์ดใหม่บนเว็บ, gate ยัง **6/6 exit 0** |

ผลลัพธ์จริงที่วัดด้วย curl: กรุงเทพมหานคร 23,529,709,183 · ชลบุรี 2,970,555,600 · สมุทรปราการ 2,779,170,000 · นนทบุรี 2,114,649,800 · ภูเก็ต 1,149,490,000 — และ `/api/summary` ยังตรงเป๊ะ

### Part B — บรีฟหนึ่งหน้าคือสัญญา

`docs/MY-FEATURE.md` เขียนสามส่วนเสมอ: ผู้ใช้เห็นอะไรเพิ่ม, ไฟล์ไหนแตะได้, อะไรห้ามแตะ (ด่าน + ยอดหลัก + คีย์) ไฟล์นี้คือสัญญาที่ทั้งผู้สั่งและผู้ทำอ้างถึงได้ ถ้าจบแล้ว scope บาน ให้ดูว่าบรีฟขาดส่วนไหน

### Part C — ทำไมแผนต้องไม่เกิน 5 ข้อ

ฟีเจอร์ที่ต้องการแผนสิบข้อยังใหญ่เกินหนึ่งรอบสั่ง ให้ตัดเหลือหนึ่งชิ้นที่เล็กที่สุดที่เปิดโชว์ได้ ที่เหลือทำรอบถัดไป — วินัยเดียวกับการตัด Module 11 ออกจากเวลาห้องเมื่อห้องช้า

## ลำดับในห้อง (ภาพรวม)

1. เขียน `docs/MY-FEATURE.md` หนึ่งหน้า (ผู้ใช้เห็นอะไร / ไฟล์ไหนแตะได้ / อะไรห้ามแตะ)
2. จังหวะแผน → ตรวจไฟล์แผนด้วยตา (ไม่เกิน 5 ข้อ)
3. จังหวะทำ → จบด้วย gate 6/6 exit 0 รายงาน exit code จริง
4. `npm start` แล้วเปิดหน้าเว็บด้วยตา ฟีเจอร์ต้องปรากฏจริง ไม่ใช่แค่คำว่าเสร็จในแชท

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ~60 นาที ถ้าย่อเหลือ 30 นาที ผ่านเมื่อมีไฟล์แผน + หน้าเว็บเปลี่ยนหนึ่งจุด ด่านยังเขียว

## Common pitfalls / กับดัก

- **ฟีเจอร์ที่แตะตัวเลขหลัก** — ถ้ายอดเปลี่ยน แม้ด่านจะยังเขียว ก็ถือว่าพัง ให้ย้อนกลับ
- **ข้ามจังหวะแผน** — แก้โค้ดตั้งแต่คำสั่งแรก คือการกลับไปวันแรกของคอร์ส
- **แผนที่ไม่รู้ว่าของเดิมมีอะไร** — แผนดีจะเจอของที่มีอยู่แล้ว (เช่น `byProvince`) แผนที่เขียนโค้ดซ้ำกับของเดิมคือแผนที่ไม่ได้อ่านโค้ด
- **เชื่อแชทโดยไม่เปิดหน้าเว็บ** — เปิดด้วยตาเสมอ (ขั้น 3 ของ LAB)

## Quick check / ทบทวน

- ฟีเจอร์ของตัวเองยังต้องผ่านด่านเดิมทำไม? — เพราะด่านคือนิยามคำว่า "ของพร้อมโชว์" ของห้อง งานใหม่ไม่มีสิทธิ์เปลี่ยนนิยาม
- รู้ได้ยังไงว่าแผนดี? — สั้น (≤5) อ้างไฟล์จริง และใช้ของที่มีอยู่ให้มากที่สุด
- ถ้าต้องการ endpoint เพิ่มอีก ทำยังไง? — รอบแผนใหม่ บรีฟใหม่ ไม่ใช่แก้ต่อจากคำสั่งเดิม
