# Module 01 — เครื่องพร้อมก่อนเข้าห้อง

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ห้องนี้ซื้อเวลาด้วยการบ้าน วิทยากรมีเวลาในห้องเท่ากันทุกคน ถ้าใครมาติดตั้งโปรแกรมในห้อง คนนั้นจะไม่ได้เรียนเลย เพราะสองเครื่องมือหลักของห้องนี้ไม่ใช่โปรแกรมที่กดติดตั้งแล้วจบ: `claude` ต้องล็อกอินด้วยบัญชีของศูนย์ฝึก และ `opencode` ต้องมีคีย์โมเดลในเครื่อง ทั้งคู่พังได้จากปัจจัยนอกโค้ด เช่น เครือข่ายองค์กรบล็อกหน้าล็อกอิน หรือ PATH ยังไม่รู้จักคำสั่งใหม่

ปัญหาที่เจอบ่อยที่สุดในห้องแบบนี้ไม่ใช่เรื่องเอเจนต์ฉลาดหรือไม่ฉลาด แต่คือเรื่องเล็ก ๆ สองเรื่อง: เปิดเครื่องมือจากผิดโฟลเดอร์ และมีค่าตั้งค้างไว้จากงานเก่า เรื่องแรก — ขอบเขตของทั้ง `claude` และ `opencode` คือ**โฟลเดอร์ที่เปิด** ไม่ใช่ทั้งเครื่อง เปิดจาก `C:\` หรือ home เอเจนต์ก็ทำงานกับขอบเขตผิดทั้งรอบ เรื่องที่สอง — ถ้าเครื่องมี `ANTHROPIC_API_KEY` ค้างไว้ Claude จะใช้คีย์นั้นแทนบัญชีคลาสทันที และค่าใช้จ่ายไปโผล่ที่บัญชีส่วนตัวแบบจ่ายตามการใช้ ไม่มีเสียงเตือนตอนเกิด

อีกเรื่องที่ต้องเห็นก่อนเข้าห้องคือ **ด่านคุณภาพเริ่มที่แดงโดยตั้งใจ** แอป Registry Insight ส่งมาพร้อมข้อมูลดิบที่ยังไม่สะอาดและโค้ดที่มีบั๊กซุกไว้ `npm run gate` จบด้วย exit 2 กับ 6 ข้อแดง นี่ไม่ใช่เครื่องพัง แต่คือจุดตั้งต้นที่ทั้งคอร์สจะพาเดินไปจนเขียว 6/6 เห็นแดงหกข้อนี้จากการบ้านก่อนถึงห้อง วันเรียนทุกคนจึงเริ่มจากความเข้าใจเดียวกันว่าแดงคือจุดตั้งต้นตามดีไซน์ และเอาเวลาไปลงกับงานจริงได้เต็มที่

> EN: Open both tools from the app folder. Labs run in the TUI. A set `ANTHROPIC_API_KEY` replaces the class subscription — it must be empty.

## Concept / เนื้อหา

### Part A — สอง repo สองเครื่องมือ

| ของ | อยู่ที่ไหน | ใครใช้ |
|---|---|---|
| repo บทเรียน `build-ai-multi-agent-hybrid` | ที่นี่ มีเฉลย | อ่านอย่างเดียว ห้ามเปิดผู้ช่วยที่นี่ |
| repo แอป `multi-agent-workshop-hybrid` | อีกโฟลเดอร์ | เปิด `claude` กับ `opencode` ที่นี่เท่านั้น |

เหตุผลง่าย ๆ: repo บทเรียนมีชุดเฉลย ถ้าเปิดผู้ช่วยในโฟลเดอร์นี้ มันจะเห็นคำตอบทั้งหมด แล็บจึงไม่มีความหมาย

### Part B — สองโหมดของทุกเครื่องมือ

| โหมด | claude | opencode | ใช้เมื่อ |
|---|---|---|---|
| TUI (มีจอ มีปุ่มกดอนุญาต) | `claude` | `opencode` | ทุกแล็บในห้อง |
| headless (จบในคำสั่งเดียว) | `claude -p "โจทย์"` | `opencode run "โจทย์"` | สคริปต์ตรวจเครื่องเท่านั้น |

แล็บทั้งหมดเริ่มด้วย **TUI** เพราะ TUI มีหน้าจอให้เห็นเครื่องมือที่กำลังทำงาน และ**มีปุ่มให้คุณกดอนุญาต**เอง ส่วนโหมด headless จบในคำสั่งเดียว ไม่มีหน้าจอให้กด สิทธิ์จึงแคบกว่า (เขียนไฟล์ใน `.claude/**` หรือรัน Bash มักถูกปฏิเสธ) คอร์สนี้ใช้ headless แค่จุดเดียว: สคริปต์ตรวจเครื่องยิง round trip สั้น ๆ หลังติดตั้ง เพื่อพิสูจน์ว่าล็อกอินและคีย์**ใช้ได้จริง** ไม่ใช่แค่ติดตั้งแล้ว

เวอร์ชันของ Claude Code ต้องอย่างน้อย **2.1.296** — รุ่นต่ำกว่านี้จะไม่มีข้อความช่วยจำ ("did you mean") เวลาสะกดชื่อฟิลด์ในไฟล์เอเจนต์ผิด ซึ่งเป็นเครื่องมือ debug ที่ Module 04 จะใช้

### Part C — ตัวแปรสองตัวที่คอร์สนี้แตะจริง

| ชื่อ | สถานะที่ถูกต้องตอนเรียน |
|---|---|
| `ANTHROPIC_API_KEY` | ต้อง**ว่าง** — มีค่าคือทับบัญชีคลาสทันที |
| `OPENROUTER_API_KEY` | ต้อง**มีค่า** — OpenCode ใช้เรียกโมเดล (สคริปต์พิมพ์แค่ความยาว ไม่พิมพ์ค่า) |

ดูค่าใน PowerShell: `echo $env:ANTHROPIC_API_KEY` · ใน bash (Mac): `echo $ANTHROPIC_API_KEY` — แล็บทั้งคอร์สไม่ต้อง `export` ตัวแปรเลย

### Part D — สคริปต์ตรวจเช็คอะไร

`scripts/readiness-check.ps1` (Windows) หรือ `readiness-check.sh` (Mac) ไล่ตรวจเป็นทอด ๆ:

| กลุ่ม | ตรวจว่าอะไร | แปลว่าอะไร |
|---|---|---|
| โครงคอร์ส | ทุก Lesson มี README/LAB ครบ, ข้อมูลจำลองครบ, ไม่มีคีย์หลุดในไฟล์ข้อความ | ของห้องพร้อม |
| เครื่องมือ | `node` 20+, `git`, `claude` 2.1.296+, `opencode` + round trip ล็อกอิน (`claude -p` ต้องตอบ `CLAUDE-OK`, `opencode run` ต้องตอบ `OC-OK`) | สองผู้ช่วยพร้อมสั่งจริง ไม่ใช่แค่ติดตั้ง |
| คีย์และความปลอดภัย | `OPENROUTER_API_KEY` มีความยาว (ไม่พิมพ์ค่า), `ANTHROPIC_API_KEY` ว่าง | บัญชีคลาสไม่ถูกคีย์ส่วนตัวทับ |
| ของคู่วันหน้า | `duckdb`, `uvx`, `vercel` (WARN ได้) | ต้องมีก่อน Module 05 / 13 |
| แอป | เจอ repo แอป, ข้อมูลจริง, พอร์ตว่าง, หน้าเว็บตอบ, ด่าน exit 2 | จุดเริ่มต้นตรงตามที่ออกแบบ |

บรรทัดสุดท้าย `verify-setup: passed` คือประตูเข้า Module 02

### Part E — สถานะเริ่มต้นของด่าน (จำไว้เทียบในห้อง)

`npm run gate` ตอนเริ่มต้องเห็นแดง 6 ชื่อพอดี: `data-quality` (ขยะใน CSV), `bad-json-does-not-crash`, `summary-matches-valid-rows`, `health-no-secrets` (ค่าตัวอย่าง `sk-...` ยังปล่อยออก), `notes-validation`, `notes-persists` — และ exit ต้องเป็น **2** เป๊ะ ๆ

### Part F — `package.json` เมนูคำสั่งของแอป (สำหรับคนที่ไม่ใช่ dev)

ในโฟลเดอร์แอปมีไฟล์ `package.json` ส่วนที่คุณต้องรู้จักมีแค่หัวข้อ `"scripts"`:

| พิมพ์ (ที่โฟลเดอร์แอป) | ความหมายจริง | ใช้เมื่อ |
|---|---|---|
| `npm start` | รัน `node server.js` — เปิดเว็บ | ดูหน้า Registry Insight |
| `npm run gate` | รัน `node scripts/quality-gate.js` — ตรวจหกเคส | ขอหลักฐานว่าแอปผ่าน/ไม่ผ่าน |
| `npm run verify` | สคริปต์ตรวจเครื่อง + บูตแอป | ทางลัดจากโฟลเดอร์แอป |

คิดง่าย ๆ: **`npm run <ชื่อ>` = กดปุ่มชื่อนั้นในเมนู** ปุ่มชี้ไปที่ไฟล์สคริปต์ คุณไม่ต้องเป็นโปรแกรมเมอร์ก็ใช้ได้ แต่**อย่าแก้ตัวตรวจ (quality-gate.js) เพื่อให้ปุ่มเขียว**

## ลงมือทำตามลำดับ (การบ้านก่อนเข้าห้อง)

1. รันสคริปต์ตรวจตาม [LAB.md](LAB.md) → อ่านบรรทัด `OK` / `WARN` / `FAIL`
2. แก้เฉพาะ `FAIL` แล้วรันใหม่จนเหลือ `verify-setup: passed`
3. จับมือครั้งแรกด้วยมือคุณเอง ครั้งเดียวพอ — เพื่อรู้ว่าสคริปต์ข้อ 1 กำลังทำอะไรให้อัตโนมัติ เปิดเทอร์มินัลที่**โฟลเดอร์แอป** (ไม่ใช่ `C:\` หรือ home) แล้ว:
   - พิมพ์ `claude` รอจอพร้อม แล้ววาง prompt จากหัวข้อถัดไป → คำตอบที่ผ่านคือ `CLAUDE-OK` เป๊ะ ๆ
   - พิมพ์ `opencode` รอจอพร้อม (โลโก้ + ช่องพิมพ์) แล้ววาง prompt รูปแบบเดียวกันแต่ขอคำตอบ `OC-OK` (ดูหัวข้อถัดไป) → ต้องได้ `OC-OK` เป๊ะ ๆ
4. เปิดแอปครั้งเดียว `npm start` → เห็นหน้า Registry Insight → Ctrl+C
5. `npm run gate` → ต้องจบ exit 2 กับแดง 6 ชื่อใน Part E — จบแดงคือถูก

## Prompt pattern — เลือกใช้อย่างใดอย่างหนึ่ง

ฝั่ง `claude` — ขอคำตอบ `CLAUDE-OK`:

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
Reply with exactly: CLAUDE-OK
```

**เวอร์ชันไทย (ใช้ได้ผลเท่ากัน):**

```text
ตอบกลับมาเป๊ะ ๆ ว่า: CLAUDE-OK
```

ฝั่ง `opencode` — รูปแบบเดียวกัน แต่คำตอบต้องเป็น `OC-OK` ตามที่สคริปต์ตรวจยิง:

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
Reply with exactly: OC-OK
```

**เวอร์ชันไทย (ใช้ได้ผลเท่ากัน):**

```text
ตอบกลับมาเป๊ะ ๆ ว่า: OC-OK
```

> 📚 **ทำไมแนะนำ EN:** ทั้งสองภาษาให้ `CLAUDE-OK` เหมือนกันเป๊ะ (ทดสอบแล้ว) — แนะนำ EN เพื่อให้ทั้งห้องอยู่ชุดคำสั่งเดียวกันตั้งแต่แล็บแรก

| ส่วน | หน้าที่ |
|---|---|
| exactly / เป๊ะ ๆ | บังคับรูปแบบคำตอบ เพื่อตรวจว่าเอเจนต์ฟังคำสั่งจริง |
| `CLAUDE-OK` / `OC-OK` | คำที่สคริปต์ตรวจได้ — ตรงกับที่ verify-setup ยิงเป๊ะ ๆ |

ถ้าจุดนี้**แดง**ในสคริปต์ตรวจ: `claude -p` ไม่ตอบ = ยังไม่ล็อกอิน (รัน `claude` แล้วสั่ง `/login`) · `opencode run` ไม่ตอบ = คีย์ยังไม่ถึง (ดู SETUP.md ข้อคีย์ OpenRouter)

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **เปิด `claude`/`opencode` จาก `C:\` หรือ home** — เอเจนต์เห็นทั้งเครื่องเป็นขอบเขต ทำงานผิดที่ได้ทั้งรอบ เปิดที่โฟลเดอร์แอปเสมอ
- **ติดตั้งแล้วสั่งไม่ได้** — PATH ของเทอร์มินัลเก่า ปิดแล้วเปิดเทอร์มินัลใหม่เสมอหลังติดตั้ง
- **alias เก่าหลังอัปเกรด Node** — ชี้ไฟล์ที่ถูกลบไปแล้ว แก้ alias ให้ชี้ติดตั้งใหม่
- **คำสั่ง env คนละรูปแบบ** — PowerShell: `$env:VAR` · bash (Mac): `$VAR` อย่าเอาคำสั่ง bash จากบทความอื่นมาพิมพ์ใน PowerShell (`export VAR=...` ใช้ไม่ได้ และแล็บไม่ต้องใช้ export เลย)
- **OpenCode ขึ้น `Database is not empty and has no session table`** — เคยเจอเมื่อติดตั้ง OpenCode รุ่น 1.x กับ 2.x ปนกัน ปิดทุกหน้าต่าง ลบ `opencode.db*` ใน `~/.local/share/opencode/` แล้วตรวจว่า `opencode --version` เป็นรุ่นเดียว (ปัจจุบันคอร์สติดตั้งด้วย `npm install -g @opencode/cli`)
- **`FAIL | OPENROUTER_API_KEY is empty`** — ต้องแก้ก่อนเข้า Module 02 เพราะ OpenCode ต้องมีโมเดลให้สั่ง เครื่องทดสอบของห้องนี้เดินช่วงเตรียมด้วยโมเดล zai ที่ล็อกอินไว้ แต่ในห้องจริงทุกเครื่องต้องผ่าน `verify-setup: passed` ก่อนไปต่อ
- **วางข้อความใน TUI ก่อนจอพร้อม** — ข้อความเพี้ยนเป็นตัวอักษรมั่วแล้วถูกส่งไปเลย รอเห็นช่องพิมพ์พร้อมแล้วค่อยวาง
- **`WARN | vercel`** — ไม่กั้นวันที่ 1 แต่ต้องมีบัญชี Vercel Hobby ก่อนวันที่ 2 (Module 13)
- **gate ไม่ exit 2** — มักเพราะเซิร์ฟเวอร์ยังเปิดอยู่ ปิด `npm start` ก่อนรันด่าน
- **คิดว่าโหมด headless ได้สิทธิ์เท่า TUI** — Bash กับ `.claude/**` ถูกปฏิเสธได้ในโหมดนี้ (เหตุผลที่แล็บเริ่มด้วย TUI ดู Part B)
- **คีย์โผล่บนจอ** — สคริปต์พิมพ์แค่ความยาวคีย์ ถ้าเห็นคีย์เต็มแปลว่าพิมพ์เอง อย่าถ่ายภาพส่ง

## Quick check / ทบทวน

- ทำไมแล็บไม่เริ่มด้วยโหมด headless (`-p` / `run`)? — แล็บต้องกดอนุญาตใน TUI เอง headless ไม่มีหน้าจอให้กดและสิทธิ์แคบกว่า คอร์สใช้แค่ในสคริปต์ตรวจเครื่อง
- ทำไมด่านเริ่มแดงและ exit 2 ถึงเป็นเรื่องดี? — เพราะมันคือจุดตั้งต้นที่วัดได้ ทุกโมดูลถัดไปจะรู้ว่าตัวเองพาด่านไปถึงไหนโดยดูตัวเลขชุดเดิม
- `WARN` กับ `FAIL` ต่างกันยังไง? — `WARN` เข้าห้องวันแรกได้แต่ต้องมีก่อนโมดูลที่กำหนด `FAIL` ต้องแก้แล้วรันใหม่จบก่อนไปต่อ
- ตรวจอะไรก่อนเปิดสองเครื่องมือ? — เวอร์ชันผ่าน (`claude` 2.1.296+), `ANTHROPIC_API_KEY` ว่าง, `OPENROUTER_API_KEY` มีค่า และเปิดจากโฟลเดอร์แอป
- ถ้าอยากเปิดผู้ช่วยดูโครงคอร์สใน repo บทเรียนได้ไหม? — ไม่ ที่นี่มีเฉลย เปิดได้เฉพาะที่โฟลเดอร์แอป
