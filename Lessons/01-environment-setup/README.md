# Module 01 — เครื่องพร้อมก่อนเข้าห้อง

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ห้องนี้ซื้อเวลาด้วยการบ้าน วิทยากรมีเวลาในห้องเท่ากันทุกคน ถ้าใครมาติดตั้งโปรแกรมในห้อง คนนั้นจะไม่ได้เรียนเลย เพราะสองเครื่องมือหลักของห้องนี้ไม่ใช่โปรแกรมที่กดติดตั้งแล้วจบ: `claude` ต้องล็อกอินด้วยบัญชีของศูนย์ฝึก และ `opencode` ต้องมีคีย์โมเดลในเครื่อง ทั้งคู่พังได้จากปัจจัยนอกโค้ด เช่น เครือข่ายองค์กรบล็อกหน้าล็อกอิน หรือ PATH ยังไม่รู้จักคำสั่งใหม่

อีกเรื่องที่ต้องเห็นก่อนเข้าห้องคือ **ด่านคุณภาพเริ่มที่แดงโดยตั้งใจ** แอป Registry Insight ส่งมาพร้อมข้อมูลดิบที่ยังไม่สะอาดและโค้ดที่มีบั๊กซุกไว้ `npm run gate` จบด้วย exit 2 กับ 6 ข้อแดง นี่ไม่ใช่เครื่องพัง แต่คือจุดตั้งต้นที่ทั้งคอร์สจะพาเดินไปจนเขียว 6/6 คนที่มาเห็นแดงครั้งแรกแล้วรู้ว่ามันคือของจริง จะไม่เสียเวลากลัวมันในวันเรียน

## Concept / เนื้อหา

### Part A — สอง repo สองเครื่องมือ

| ของ | อยู่ที่ไหน | ใครใช้ |
|---|---|---|
| repo บทเรียน `build-ai-multi-agent-hybrid` | ที่นี่ มีเฉลย | อ่านอย่างเดียว ห้ามเปิดผู้ช่วยที่นี่ |
| repo แอป `multi-agent-workshop-hybrid` | อีกโฟลเดอร์ | เปิด `claude` กับ `opencode` ที่นี่เท่านั้น |

เหตุผลง่าย ๆ: repo บทเรียนมีชุดเฉลย ถ้าเปิดผู้ช่วยในโฟลเดอร์นี้ มันจะเห็นคำตอบทั้งหมด แล็บจึงไม่มีความหมาย

### Part B — สคริปต์ตรวจเช็คอะไร

`scripts/readiness-check.ps1` (Windows) หรือ `readiness-check.sh` (Mac) ไล่ตรวจเป็นทอด ๆ:

| กลุ่ม | ตรวจว่าอะไร | แปลว่าอะไร |
|---|---|---|
| โครงคอร์ส | ทุก Lesson มี README/LAB ครบ, ข้อมูลจำลองครบ, ไม่มีคีย์หลุดในไฟล์ข้อความ | ของห้องพร้อม |
| เครื่องมือ | `node` 20+, `git`, `claude` 2.1.296+, `opencode` | สองผู้ช่วยพร้อมสั่ง |
| คีย์และความปลอดภัย | `OPENROUTER_API_KEY` มีความยาว (ไม่พิมพ์ค่า), `ANTHROPIC_API_KEY` ว่าง | บัญชีคลาสไม่ถูกคีย์ส่วนตัวทับ |
| ของคู่วันหน้า | `duckdb`, `uvx`, `vercel` (WARN ได้) | ต้องมีก่อน Module 05 / 13 |
| แอป | เจอ repo แอป, ข้อมูลจริง, พอร์ตว่าง, หน้าเว็บตอบ, ด่าน exit 2 | จุดเริ่มต้นตรงตามที่ออกแบบ |

บรรทัดสุดท้าย `verify-setup: passed` คือประตูเข้า Module 02

### Part C — สถานะเริ่มต้นของด่าน (จำไว้เทียบในห้อง)

`npm run gate` ตอนเริ่มต้องเห็นแดง 6 ชื่อพอดี: `data-quality` (ขยะใน CSV), `bad-json-does-not-crash`, `summary-matches-valid-rows`, `health-no-secrets` (ค่าตัวอย่าง `sk-...` ยังปล่อยออก), `notes-validation`, `notes-persists` — และ exit ต้องเป็น **2** เป๊ะ ๆ

## ลำดับในห้อง (ภาพรวม)

1. รันสคริปต์ตรวจ → อ่านบรรทัด `OK` / `WARN` / `FAIL`
2. แก้เฉพาะ `FAIL` แล้วรันใหม่จนเหลือ `verify-setup: passed`
3. เปิดแอปครั้งเดียว `npm start` → เห็นหน้า Registry Insight → Ctrl+C
4. `npm run gate` → ต้องจบ exit 2 — จบแดงคือถูก

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **ติดตั้งแล้วสั่งไม่ได้** — PATH ของเทอร์มินัลเก่า ปิดแล้วเปิดเทอร์มินัลใหม่เสมอหลังติดตั้ง
- **OpenCode ขึ้น `Database is not empty and has no session table`** — เคยเจอเมื่อติดตั้ง OpenCode รุ่น 1.x กับ 2.x ปนกัน ปิดทุกหน้าต่าง ลบ `opencode.db*` ใน `~/.local/share/opencode/` แล้วตรวจว่า `opencode --version` เป็นรุ่นเดียว (ปัจจุบันคอร์สติดตั้งด้วย `npm install -g @opencode/cli`)
- **`FAIL | OPENROUTER_API_KEY is empty`** — ต้องแก้ก่อนเข้า Module 02 เพราะ OpenCode ต้องมีโมเดลให้สั่ง เครื่องทดสอบของห้องนี้เดินช่วงเตรียมด้วยโมเดล zai ที่ล็อกอินไว้ แต่ในห้องจริงทุกเครื่องต้องผ่าน `verify-setup: passed` ก่อนไปต่อ
- **`WARN | vercel`** — ไม่กั้นวันที่ 1 แต่ต้องมีบัญชี Vercel Hobby ก่อนวันที่ 2 (Module 13)
- **gate ไม่ exit 2** — มักเพราะเซิร์ฟเวอร์ยังเปิดอยู่ ปิด `npm start` ก่อนรันด่าน
- **คีย์โผล่บนจอ** — สคริปต์พิมพ์แค่ความยาวคีย์ ถ้าเห็นคีย์เต็มแปลว่าพิมพ์เอง อย่าถ่ายภาพส่ง

## Quick check / ทบทวน

- ทำไมด่านเริ่มแดงและ exit 2 ถึงเป็นเรื่องดี? — เพราะมันคือจุดตั้งต้นที่วัดได้ ทุกโมดูลถัดไปจะรู้ว่าตัวเองพาด่านไปถึงไหนโดยดูตัวเลขชุดเดิม
- `WARN` กับ `FAIL` ต่างกันยังไง? — `WARN` เข้าห้องวันแรกได้แต่ต้องมีก่อนโมดูลที่กำหนด `FAIL` ต้องแก้แล้วรันใหม่จบก่อนไปต่อ
- ถ้าอยากเปิดผู้ช่วยดูโครงคอร์สใน repo บทเรียนได้ไหม? — ไม่ ที่นี่มีเฉลย เปิดได้เฉพาะที่โฟลเดอร์แอป
