# Module 02 — ให้ผู้ช่วยรู้จักงานก่อนสั่ง

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ผู้ช่วย AI ไม่รู้จักงานของเราจนกว่าเราจะเล่า ถ้าปล่อยมันเดา มันจะเดาจากชื่อไฟล์และโค้ดที่เห็น แล้วลงมือแก้ผิดที่ ไฟล์กติกาทั้งสองจึงเหมือนบรีฟพนักงานใหม่ ไม่ใช่ตัวโปรแกรม: `CLAUDE.md` คือบรีฟของ Claude Code, `AGENTS.md` คือบรีฟของ OpenCode ทั้งคู่ถูกอ่านอัตโนมัติทุกครั้งที่เปิดเครื่องมือที่โฟลเดอร์แอป ถ้าเขียนไว้ดี ทุกคำสั่งถัดไปจะง่ายขึ้นทั้งวัน

แต่บรีฟไม่ได้มีประโยชน์เพียงเพราะเขียนแล้ว แต่เพราะ**มีคนตรวจว่ากฎสำคัญยังอยู่ครบ** แล็บนี้จึงไม่ใช่แล็บเขียนเอกสาร แต่เป็นแล็บฝึกวินัยสองอย่างพร้อมกัน: ให้เครื่องมือเติมกติกาที่ขาดเอง แล้วให้เราเปิดไฟล์ด้วยตาว่ากฎตายตัวไม่หาย สิ่งที่ทำให้วินัยนี้วัดได้คือเทสต์ชุดเริ่มของแอปที่มีเคส `rules match on both tools` ซึ่งจับดูว่าคำสำคัญ (`scripts/quality-gate.js`, `data/notes.json`, `VERCEL`, `OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `notes-persists`) ต้องอยู่ครบทั้งสองไฟล์ ถ้าใครลบกฎพลาด เทสเด้งทันที

## Concept / เนื้อหา

### Part A — ไฟล์กติกาทำงานยังไง

| ไฟล์ | ใครอ่าน | อยู่ไหน |
|---|---|---|
| `CLAUDE.md` | Claude Code อ่านอัตโนมัติเมื่อเปิดที่โฟลเดอร์ | รากของ repo แอป |
| `AGENTS.md` | OpenCode อ่านอัตโนมัติเมื่อเปิดที่โฟลเดอร์ | รากของ repo แอป |
| `opencode.json` | ตั้งค่า provider/permission ของ OpenCode | รากของ repo แอป ห้ามวางค่าคีย์ |

กฎที่เขียนในฝั่งหนึ่งต้องตรงกับอีกฝั่ง ไม่งั้นสองเครื่องมือจะได้บรีฟคนละใบ แล้วทำงานสวนกัน ในโมดูลนี้เรายังไม่สร้าง `vercel.json` หรือ `api/`

จุดสำคัญตอนรัน `/init` ใน OpenCode: ถ้าโฟลเดอร์มีทั้ง `CLAUDE.md` และ `AGENTS.md` OpenCode จะอ่านเฉพาะ `AGENTS.md` เท่านั้น กติกาฝั่ง OpenCode จึงต้องครบอยู่ในไฟล์นี้ การเขียนอ้างว่า "ดูต่อใน `CLAUDE.md`" ไม่ช่วย เพราะมันไม่ไปอ่านไฟล์นั้น ฝั่ง Claude Code ก็อ่าน `CLAUDE.md` เป็นบรีฟของมันเช่นกัน — สองไฟล์ต้องมีกฎชุดเดียวกันซ้ำอยู่ทั้งคู่ ไม่ใช่แบ่งกันคนละครึ่งแล้วชี้มาหากัน

### Part B — `/init` ทำอะไรจริง (จากเครื่องทดสอบ claude 2.1.318)

- ครั้งแรกที่ใช้กับโฟลเดอร์จะมีหน้าถามความไว้ใจ (`Yes, I trust this folder`) รอบถัดไปไม่ถามซ้ำ
- `/init` ไม่ถามยืนยัน รันสำรวจทันที (อ่าน `server.js`, `scripts/quality-gate.js`, `lib/inspect-data.js` แล้วจบในประมาณหนึ่งนาที)
- ถ้าเจอไฟล์กติกาเดิมอยู่แล้ว มันจะ**เติม** ไม่ทับ: รอบทดสอบแตะ `CLAUDE.md` +29 บรรทัด −1 โดยเพิ่มหัวไฟล์ หัวข้อคำสั่ง (`npm start/gate/test/verify`) และแผนที่ด่าน 6 เคส กฎเดิมทุกข้อยังอยู่
- มันอาจเสริมประโยคกฎให้ชัดขึ้น เช่น กฎ `sk-` กลายเป็น "อย่าอ่าน/คัดลอก/พิมพ์ค่าออกมาในคำตอบ log หรือผลคำสั่ง (ปิดเป็น `sk-***`)" — อันนี้อนุญาต เพราะยังไม่ลบกฎทั้งข้อ

### Part C — ฝั่ง OpenCode: `/init` แล้วเติมเฉพาะที่ขาด

ชุดเริ่มให้ `AGENTS.md` มาครบแล้ว งานจริงของ OpenCode ในขั้นนี้คืออ่านสองไฟล์ก่อน แล้วเติมเฉพาะบรรทัดที่ยังไม่มี — ห้ามเขียนทับทั้งไฟล์ จากเครื่องทดสอบ (opencode 2.2.5, โมเดลสาธิตของศูนย์ฝึก) รอบที่วางพรอมต์ตรง ๆ มันตรวจแล้วรายงานว่าข้อความบังคับครบทุกหัวข้อและตรงกับของจริงใน repo แล้วจึงไม่แตะไฟล์ — นี่คือผลที่ผ่าน ไม่ใช่ความล้มเหลว รอบ `/init` จริง (2.2.6, 1m36s) ยืนยันพฤติกรรมเดียวกันแบบเห็นกลไก: มันตรวจข้ออ้างกับซอร์สก่อนเขียน (จับ conflict เรื่องจำนวนคอลัมน์ 9 กับ 8 ระหว่าง `lib/inspect-data.js` กับ `CLAUDE.md` ได้เอง) เติมเฉพาะที่ขาด (+33/−4) และเมื่อบรรทัดจากพรอมต์ขัดแผนที่คลาสใน repo มันถามก่อนแล้วจึงใส่ ไม่ใช่เขียนตามคำสั่งไปเงียบ ๆ — แล็บนี้วัดวินัยอ่านก่อนเขียน ไม่ใช่จำนวนบรรทัดที่เพิ่ม

### Part D — อบอุ่นสมองก่อนปิดแล็บ: ไฟล์เสี่ยงสุด และคำถามตัดสินของคอร์ส

คุยกับผู้ช่วยอีกหนึ่งรอบด้วยพรอมต์เดียว (เลือกอย่างใดอย่างหนึ่ง — พิมพ์ใน `claude` หรือ `opencode` ก็ได้):

**เวอร์ชันอังกฤษ (แนะนำ):**

```text
Explore this project for 2 minutes and name the single riskiest file. Under 80 words.
```

**เวอร์ชันไทย (ใช้ได้ผลเท่ากัน):**

```text
สำรวจโปรเจกต์นี้ประมาณ 2 นาที แล้วบอกไฟล์เดียวที่เสี่ยงที่สุด พร้อมเหตุผล ไม่เกิน 80 คำ
```

> 📚 **ทำไมแนะนำ EN:** ภาษาของ prompt เป็นตัวกำหนดภาษาของคำตอบ — ทั้งห้องใช้ภาษาเดียวกันจึงเทียบคำตอบกันได้ตรง ๆ ส่วน TH ใช้ได้เต็มที่ ชื่อไฟล์และ endpoint ในคำตอบยังถูกพิมพ์ถูกต้องเสมอ

| ส่วนของพรอมต์ | หน้าที่ |
|---|---|
| เวลา | กันไม่ให้สำรวจทั้ง repo |
| ไฟล์เดียว | บังคับให้เลือก ไม่ใช่รายการยาว |
| ไม่เกิน 80 คำ | กันรายงานยาวจน leader อ่านไม่ไหว |

แล้วถามต่อหนึ่งประโยค: งานที่เหลือควรทำแบบ swarm หรือ sequential — นี่คือ**คำถามตัดสินเดียวของทั้งคอร์ส**: งานขั้นถัดไปต้องใช้ผลของขั้นก่อนหน้าหรือไม่ ถ้าไม่ต้องก็แตกขนานได้ ถ้าต้องก็ให้ต่อคิว ทุกโมดูลถัดไปใช้คำถามนี้ตัดสิน ในคลาสไฮบริดมีขั้นเลือกเครื่องมือมาก่อนคำถามนี้: งานสายข้อมูล-หลังบ้าน-หน้าเว็บใช้ OpenCode ส่วนงานสำรวจ-ปิดด่าน-สรุปใช้ Claude Code ตามผังใน `AGENTS.md`

### Part E — เช็กลิสต์ตรวจด้วยตา (คือเกณฑ์ "ผ่านเมื่อ")

1. `CLAUDE.md` ยังพูดถึง quality gate และห้ามแก้ `scripts/quality-gate.js`
2. `AGENTS.md` ยังมีทั้ง Claude Code และ OpenCode, `OPENROUTER_API_KEY`, และ `ANTHROPIC_API_KEY` ต้องว่าง
3. ยังไม่มี `vercel.json` และไม่มีโฟลเดอร์ `api/`
4. `git diff` ไม่แตะ `server.js` และไม่แตะไฟล์ใน `data/`

ปิดท้ายรัน `npm test` ต้องผ่าน 7/7 รวมเคส `rules match on both tools` และ `npm run gate` ยังต้องแดงที่ exit 2 ตามตั้งต้น — โมดูลนี้ไม่ได้ทำให้ด่านเขียว มันแค่ทำให้ผู้ช่วยรู้กติกาก่อนลงมือ

## ลำดับในห้อง (ภาพรวม)

1. เปิดเทอร์มินัลที่โฟลเดอร์แอป → `claude` → ผ่านหน้า trust → `/init` → วางพรอมต์ตรวจกติกา → อ่านสรุป 5 บรรทัด → `/exit`
2. เปิดไฟล์ `CLAUDE.md` ด้วยตา ตามเช็กลิสต์ข้อ 1
3. เทอร์มินัลใหม่ → `opencode` → `/init` → วางพรอมต์ให้เติม `AGENTS.md` เฉพาะที่ขาด → อ่านคำยืนยัน → `/exit`
4. อบอุ่นสมอง: พรอมต์ไฟล์เสี่ยงสุด (ไม่เกิน 80 คำ) → ถามต่อว่า swarm หรือ sequential
5. เช็กลิสต์ข้อ 2–4 + `npm test` + `npm run gate`

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 45 นาที

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **วางข้อความหลายบรรทัดใน claude แล้วข้อความไม่ลงในช่องพิมพ์** — ใช้คลิปบอร์ดแล้ว Ctrl+V ในช่องพิมพ์ จะเห็นข้อความครบในกล่องก่อนกด Enter (ถ้าข้อความยาวมันจะเสนอ `ctrl+g` เปิดแก้ใน Notepad ได้) ถ้ากด Enter ตอนช่องยังว่างจะส่งพรอมต์เก่าที่ค้างอยู่แทน
- **opencode บ่น `Rate limit reached`** — เครื่องทดสอบเจอ attempt ที่ 4 ให้รอเฉย ๆ มัน retry เองแล้วทำงานต่อจนจบ (ประมาณหนึ่งนาที) อย่ากด Esc ออกกลางทาง
- **โมเดล opencode ชี้ไป provider ที่ไม่มีคีย์** — ต้องตั้ง `OPENCODE_MODEL` ตาม SETUP.md ก่อนรัน เครื่องทดสอบใช้โมเดลสาธิตของศูนย์ฝึก ถ้าลืมตั้ง มันจะพยายามไปที่โมเดล OpenRouter แล้วตายตั้งแต่คำสั่งแรก
- **`/init` ทับกฎเดิม?** — จากรอบทดสอบไม่ทับ มันเติม แต่ห้ามไว้ใจลอย ๆ ให้เปิด `git diff CLAUDE.md AGENTS.md` ดูเสมอ ต้องเห็นเฉพาะบรรทัดที่เพิ่มกับประโยคกฎที่ชัดขึ้น ไม่มีบล็อกกฎใดถูกลบ
- **หน้าต่างเสียฟอกัสระหว่างพิมพ์** — ถ้าสลับไปพิมพ์ที่หน้าต่างอื่น TUI จะไม่รับคีย์ คลิกหน้าต่างเทอร์มินัลกลับมาก่อนพิมพ์ต่อ
- **พรอมต์บอก "Module 13" แต่ใน repo บอก "Lab 11"** — ไฟล์ของแอป (`CLAUDE.md`, `server.js` หัวไฟล์, `reference/vercel/README.md` ในบทเรียน) ยังพูดถึง Lab 11 อยู่ ในรอบทดสอบ 2.2.6 ผู้ช่วยจึงไม่ใส่บรรทัดนั้นตามพรอมต์ แต่ถามก่อน — ใช้ตอนนี้เป็นจุดสอนว่าการอ่านก่อนเขียนทำงานจริง และผู้สอนควรยืนยันเลขโมดูลให้ห้องตัดสินใจตรงกัน

## Quick check / ทบทวน

- ทำไมไม่เขียน `CLAUDE.md` ใหม่ทั้งไฟล์ด้วยตัวเองให้เรียบร้อยไปเลย? — เพราะวินัยที่ต้องฝึกคือตรวจของเดิมก่อนเขียนใหม่ ไฟล์ที่มีอยู่มีกฎตายตัวที่เทสจับอยู่ เขียนทับง่ายกว่าแต่เสี่ยงลบกฎ
- `/init` เสริมประโยคกฎให้ยาวขึ้น นับว่าลบกฎไหม? — ไม่ ขอแค่ให้ความหมายห้ามยังอยู่ครบและเทสยังผ่าน
- ถ้า OpenCode บอกว่า `AGENTS.md` ครบอยู่แล้ว แล็บนี้ผมไม่ได้ทำอะไรเลยหรือ? — ทำแล้ว คุณพิสูจน์ว่าบรีฟทั้งสองฝั่งสอดคล้องกันและกฎครบ ซึ่งเป็นจุดตั้งต้นของทุกโมดูลถัดไป
- รัน `/init` ใน OpenCode แล้ว กฎที่อยู่ใน `CLAUDE.md` จะถูก OpenCode อ่านไหม? — ไม่ ถ้ามี `AGENTS.md` อยู่ด้วย OpenCode อ่านเฉพาะ `AGENTS.md` OpenCode จึงมองไม่เห็นกฎที่อยู่แค่ใน `CLAUDE.md` นี่คือเหตุผลที่เทส `rules match on both tools` บังคับให้กฎครบเท่ากันทั้งสองไฟล์
- งานที่เหลือควรทำแบบ swarm หรือ sequential ตัดสินด้วยอะไร? — ดูว่าขั้นถัดไปต้องใช้ผลของขั้นก่อนหรือไม่ ไม่ต้องใช้ก็ขนานได้ ต้องใช้ก็ต่อคิว ในคลาสนี้เลือกเครื่องมือตามผังใน `AGENTS.md` ก่อน แล้วค่อยถามคำถามนี้

## Go deeper

- เปิด `git log -p CLAUDE.md` ดูว่า `/init` เปลี่ยนอะไรไปบ้างเทียบกับชุดเริ่ม
- ลองถาม claude ต่อว่า "สรุปกฎ 5 ข้อที่ห้ามฝ่าในแอปนี้" เทียบกับที่เขียนในไฟล์ เหมือนหรือเพี้ยนตรงไหน
