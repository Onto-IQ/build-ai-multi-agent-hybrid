# Module 02 — ให้ผู้ช่วยรู้จักงานก่อนสั่ง

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ผู้ช่วย AI ไม่รู้จักงานของเราจนกว่าเราจะเล่า ถ้าปล่อยมันเดา มันจะเดาจากชื่อไฟล์และโค้ดที่เห็น แล้วลงมือแก้ผิดที่ ไฟล์กติกาสองตัวนี้จึงเป็นบรีฟพนักงานใหม่ ไม่ใช่ตัวโปรแกรม: `CLAUDE.md` คือบรีฟของ Claude Code, `AGENTS.md` คือบรีฟของ OpenCode ทั้งคู่ถูกอ่านอัตโนมัติทุกครั้งที่เปิดเครื่องมือที่โฟลเดอร์แอป เขียนดีแล้วทุกคำสั่งถัดไปจะง่ายขึ้นทั้งวัน

แต่บรีฟไม่ได้มีประโยชน์เพราะเขียนแล้ว มีประโยชน์เพราะ**มีคนตรวจว่ากฎสำคัญยังอยู่ครบ** แล็บนี้จึงไม่ใช่แล็บเขียนเอกสาร แต่เป็นแล็บฝึกวินัยสองอย่างพร้อมกัน: ให้เครื่องมือเติมกติกาที่ขาดเอง แล้วให้เราเปิดไฟล์ด้วยตาว่ากฎตายตัวไม่หาย สิ่งที่ทำให้วินัยนี้วัดได้คือเทสต์ชุดเริ่มของแอปที่มีเคส `rules match on both tools` ซึ่งจับคำสำคัญ (`scripts/quality-gate.js`, `data/notes.json`, `VERCEL`, `OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `notes-persists`) ว่าต้องอยู่ครบทั้งสองไฟล์ ถ้าใครลบกฎพลาด เทสเด้งทันที

## Concept / เนื้อหา

### Part A — ไฟล์กติกาทำงานยังไง

| ไฟล์ | ใครอ่าน | อยู่ไหน |
|---|---|---|
| `CLAUDE.md` | Claude Code อ่านอัตโนมัติเมื่อเปิดที่โฟลเดอร์ | รากของ repo แอป |
| `AGENTS.md` | OpenCode อ่านอัตโนมัติเมื่อเปิดที่โฟลเดอร์ | รากของ repo แอป |
| `opencode.json` | ตั้งค่า provider/permission ของ OpenCode | รากของ repo แอป ห้ามวางค่าคีย์ |

กฎที่เขียนในฝั่งหนึ่งต้องตรงกับอีกฝั่ง ไม่งั้นสองเครื่องมือจะได้บรีฟคนละใบ แล้วทำงานสวนกัน ยังไม่สร้าง `vercel.json` หรือ `api/` ในโมดูลนี้

จุดสำคัญตอนรัน `/init` ใน OpenCode: ถ้าโฟลเดอร์มีทั้ง `CLAUDE.md` และ `AGENTS.md` OpenCode อ่านเฉพาะ `AGENTS.md` เท่านั้น กติกาฝั่ง OpenCode จึงต้องครบอยู่ในไฟล์นี้ การเขียนอ้างว่า "ดูต่อใน `CLAUDE.md`" ไม่ช่วย เพราะมันไม่ไปอ่านไฟล์นั้น ฝั่ง Claude Code ก็อ่าน `CLAUDE.md` เป็นบรีฟของมันเช่นกัน — สองไฟล์ต้องมีกฎเดียวกันซ้ำกันคนละใบ ไม่ใช่แบ่งเนื้อหาครึ่งเดียวแล้วเชื่อมกัน

### Part B — `/init` ทำอะไรจริง (จากเครื่องทดสอบ claude 2.1.318)

- ครั้งแรกต่อโฟลเดอร์จะมีหน้าถามความไว้ใจ (`Yes, I trust this folder`) รอบถัดไปไม่ถามซ้ำ
- `/init` ไม่ถามยืนยัน รันสำรวจทันที (อ่าน `server.js`, `scripts/quality-gate.js`, `lib/inspect-data.js` แล้วจบในประมาณหนึ่งนาที)
- เจอไฟล์กติกาเดิมอยู่แล้วมันจะ**เติม** ไม่ทับ: รอบทดสอบแตะ `CLAUDE.md` +29 บรรทัด −1 โดยเพิ่มหัวไฟล์ ส่วนคำสั่ง (`npm start/gate/test/verify`) และแผนที่ด่าน 6 เคส กฎเดิมทุกข้อยังอยู่
- มันอาจเสริมประโยคกฎให้ชัดขึ้น เช่น กฎ `sk-` กลายเป็น "อย่าอ่าน/คัดลอก/พิมพ์ค่าออกมาในคำตอบ log หรือผลคำสั่ง (ปิดเป็น `sk-***`)" — อนุญาต เพราะยังไม่ลบทั้งข้อ

### Part C — ทำไมให้ OpenCode "เติมเฉพาะที่ขาด" แล้วมันรายงานว่าครบ

ชุดเริ่มให้ `AGENTS.md` มาครบแล้ว งานจริงของ OpenCode ในขั้นนี้คืออ่านสองไฟล์ แล้วสรุปว่าข้อความบังคับครบ จากเครื่องทดสอบ (opencode 2.2.5, `zai/glm-4.7-flash`) มันรายงานว่าข้อความบังคับครบทุกหัวข้อตรงกับสนามจริง แล้วไม่แตะไฟล์ — นี่คือผ่าน แล็บนี้วัดวินัยการอ่านก่อนเขียน ไม่ใช่จำนวนบรรทัดที่เพิ่ม

### Part D — เช็กลิสต์ตรวจด้วยตา (คือเกณฑ์ "ผ่านเมื่อ")

1. `CLAUDE.md` ยังพูดถึง quality gate และห้ามแก้ `scripts/quality-gate.js`
2. `AGENTS.md` ยังมีทั้ง Claude Code และ OpenCode, `OPENROUTER_API_KEY`, และ `ANTHROPIC_API_KEY` ต้องว่าง
3. ยังไม่มี `vercel.json` และไม่มีโฟลเดอร์ `api/`
4. `git diff` ไม่แตะ `server.js` และไม่แตะไฟล์ใน `data/`

ปิดท้ายรัน `npm test` ต้องผ่าน 7/7 รวมเคส `rules match on both tools` และ `npm run gate` ยังต้องแดง exit 2 อยู่พอดี — โมดูลนี้ไม่ได้ทำให้ด่านเขียว มันแค่ทำให้ผู้ช่วยรู้กติกาก่อนลงมือ

## ลำดับในห้อง (ภาพรวม)

1. เปิดเทอร์มินัลที่โฟลเดอร์แอป → `claude` → ผ่านหน้า trust → `/init` → วางพรอมต์ตรวจกติกา → อ่านสรุป 5 บรรทัด → `/exit`
2. เปิดไฟล์ `CLAUDE.md` ด้วยตา ตามเช็กลิสต์ข้อ 1
3. เทอร์มินัลใหม่ → `opencode` → วางพรอมต์เติม `AGENTS.md` → อ่านคำยืนยัน → `/exit`
4. เช็กลิสต์ข้อ 2–4 + `npm test` + `npm run gate`

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 40 นาที

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **วางข้อความหลายบรรทัดใน claude แล้วไม่ตก** — ใช้คลิปบอร์ดแล้ว Ctrl+V ในช่องพิมพ์ จะเห็นข้อความครบในกล่องก่อนกด Enter (ข้อความยาวมันเสนอ `ctrl+g` เปิดแก้ใน Notepad ได้) ถ้ากด Enter ตอนช่องยังว่างจะส่งคำแนะนำเก่าที่ค้างอยู่แทน
- **opencode บ่น `Rate limit reached`** — เครื่องทดสอบเจอ attempt 4 ให้รอเฉย ๆ มัน retry เองแล้วทำงานต่อจนจบ (ประมาณหนึ่งนาที) อย่ากด Esc หนีกลางทาง
- **โมเดล opencode ชี้ไป provider ที่ไม่มีคีย์** — ต้องตั้ง `OPENCODE_MODEL` ตาม SETUP.md ก่อนรัน เครื่องทดสอบใช้ `zai/glm-4.7-flash` ถ้าลืมตั้งมันจะพยายามไปโมเดล OpenRouter แล้วตายตั้งแต่คำสั่งแรก
- **`/init` ทับกฎเดิม?** — จากรอบทดสอบไม่ทับ มันเติม แต่ห้ามไว้ใจลอย ๆ ให้เปิด `git diff CLAUDE.md` ดูเสมอ ต้องเห็นเฉพาะบวกกับประโยคกฎที่ชัดขึ้น ไม่มีบล็อกกฎใดถูกลบ
- **หน้าต่างเสียฟอกัสระหว่างพิมพ์** — ถ้าสลับไปพิมพ์หน้าต่างอื่น TUI จะไม่รับคีย์ คลิกหน้าต่างเทอร์มินัลกลับมาก่อนพิมพ์ต่อ

## Quick check / ทบทวน

- ทำไมไม่เขียน `CLAUDE.md` ใหม่ทั้งไฟล์เองให้เรียบร้อยไปเลย? — เพราะวินัยที่ต้องฝึกคือตรวจของเดิมก่อนเขียนใหม่ ไฟล์ที่มีอยู่มีกฎตายตัวที่เทสจับอยู่ เขียนทับง่ายกว่าแต่เสี่ยงลบกฎ
- `/init` เสริมประโยคกฎให้ยาวขึ้น นับว่าลบกฎไหม? — ไม่ ขอแค่ความหมายห้ามยังอยู่ครบและเทสยังผ่าน
- ถ้า OpenCode บอกว่า `AGENTS.md` ครบอยู่แล้ว แล็บนี้ผมไม่ได้ทำอะไรเลยหรือ? — ทำแล้ว คุณพิสูจน์ว่าบรีฟทั้งสองฝั่งสอดคล้องกันและกฎครบ ซึ่งเป็นพื้นที่ยืนของทุกโมดูลถัดไป
- รัน `/init` ใน OpenCode แล้ว กฎที่อยู่ใน `CLAUDE.md` จะถูก OpenCode อ่านไหม? — ไม่ ถ้ามี `AGENTS.md` อยู่ด้วย OpenCode อ่านเฉพาะ `AGENTS.md` กฎที่อยู่แค่ใน `CLAUDE.md` จึงมองไม่เห็นสำหรับ OpenCode นี่คือเหตุผลที่เทส `rules match on both tools` บังคับให้กฎครบเท่ากันทั้งสองไฟล์

## Go deeper

- เปิด `git log -p CLAUDE.md` ดูว่า `/init` เปลี่ยนอะไรไปบ้างเทียบกับชุดเริ่ม
- ลองถาม claude ต่อว่า "สรุปกฎ 5 ข้อที่ห้ามฝ่าในแอปนี้" เทียบกับที่เขียนในไฟล์ เหมือนหรือเพี้ยนตรงไหน
