# Module 07 — เช็กลิสต์งานที่ทำซ้ำ

## Key idea / แนวคิดหลัก — เล่าเป็นเรื่อง

ทุกครั้งที่จะปล่อยของ คนทำงานต้องถามชุดคำถามเดิม: เซิร์ฟเวอร์เปิดได้ไหม health ปล่อยของลับไหม ปิดเซิร์ฟเวอร์ก่อนรันด่านหรือยัง exit code เป็นเท่าไร ครั้งแรกเราพิมพ์คำถามพวกนี้ให้ผู้ช่วยเอง ครั้งที่สิบมันกลายเป็นงานพิมพ์ซ้ำ skill คือทางแก้: เก็บขั้นตอนไว้ในไฟล์ `.claude/skills/<ชื่อ>/SKILL.md` แล้วผู้ช่วยหยิบไปใช้เองเมื่องานตรง description

สิ่งที่ทำให้ skill ต่างจากโน้ตที่วางไว้ในโฟลเดอร์คือ **มันถูกเรียกใช้ได้จริงและต้องรายงานผลที่วัดได้** รอบทดสอบจริงเรียก skill `release-checklist` แล้วได้ตาราง PASS/FAIL สี่ข้อ จบด้วย `GATE_EXIT=0, quality gate: 6/6 passed` — ไม่ใช่คำชม แต่คือหลักฐานที่วัดซ้ำได้

## Concept / เนื้อหา

### Part A — สองไฟล์ของโมดูลนี้ (จากเครื่องทดสอบจริง)

| ไฟล์ | หน้าที่ |
|---|---|
| `.claude/skills/release-checklist/SKILL.md` | frontmatter `name` + `description` ภาษาอังกฤษ (Use before releasing the Registry Insight app) เนื้อหาคือสี่ข้อตรวจตามลำดับ |
| `.claude/agents/release-manager.md` | agent ที่มี Bash ใน tools และผูกกับ skill นี้ — คนที่ "ทำหน้าที่ปล่อยของ" |

### Part B — สี่ข้อของเช็กลิสต์และผลจริง

| ข้อ | ผลรอบทดสอบ |
|---|---|
| 1. เซิร์ฟเวอร์เปิดได้ | PASS |
| 2. `/api/health` ไม่มี `sk-` (ห้ามพิมพ์ค่า) | PASS — นับจำนวนคำว่า sk- ได้ 0, sampleToken 0, ok:true |
| 3. ปิดเซิร์ฟเวอร์ก่อนรันด่าน | PASS — ปิด PID ทิ้ง port 3000 free |
| 4. `npm run gate` บันทึก exit code จริง | PASS — **GATE_EXIT=0, 6/6 passed** |

ข้อ 2 สอนอะไรแพงที่สุด: การตรวจความปลอดภัยต้องออกแบบให้ผู้ตรวจ**ไม่จำเป็นต้องเห็นค่าลับ** (นับจำนวนรูปแบบ ไม่อ่านค่า) สอดคล้องกฎ "ห้ามพิมพ์ค่าที่ขึ้นต้นด้วย sk-" มาตั้งแต่ Module 01

### Part C — skill อยู่กับ repo

skill กับ agent ถูก commit ลง repo คนถัดไปที่โคลนมาได้เช็กลิสต์ชุดเดิมทันที ไม่ต้องถามว่า "ก่อนปล่อยต้องเช็กอะไรบ้าง"

## ลำดับในห้อง (ภาพรวม)

1. สั่งสร้างสองไฟล์ → ตรวจด้วยตาว่ามีจริง
2. ปิดเปิด claude ใหม่ (skill โหลดตอนเปิดรอบใหม่)
3. สั่ง "ใช้ release checklist ตรวจแอปนี้" → อ่านตาราง PASS/FAIL + exit code จริง

แบบฝึกหัดเต็มอยู่ที่ [LAB.md](LAB.md) ประมาณ 25 นาที

## Common pitfalls / กับดัก (จากเครื่องทดสอบจริง)

- **skill ไม่โหลดเพราะยังไม่ปิดเปิดใหม่** — skill ถูกอ่านตอนเปิดรอบ เหมือนไฟล์ agent
- **description ไทยหรือกำกวม** — description คือเกณฑ์ที่ผู้ช่วยตัดสินว่าจะหยิบ skill นี้เมื่อไร ให้เป็นอังกฤษชี้สถานการณ์ชัด
- **เช็กลิสต์ที่ "รันแล้วเงียบ"** — ทุกข้อต้องจบด้วยหลักฐาน (ตัวเลข, exit code) ไม่ใช่คำว่า "ดู OK แล้ว"
- **ใส่คีย์ไว้ใน skill** — skill คือวิธีทำงาน ไม่ใช่ที่เก็บค่า ค่าควรมาจากตัวแปรสภาพแวดล้อมเสมอ

## Quick check / ทบทวน

- ต่างจากคำสั่งวางซ้ำ ๆ ยังไง? — skill อยู่ใน repo โหลดเอง ใช้ซ้ำได้โดยไม่ต้องจำข้อความ
- ข้อ 3 (ปิดเซิร์ฟเวอร์ก่อนรันด่าน) มาจากไหน? — จากด่านเอง: ถ้าพอร์ต 3000 ถูกใช้ เคสฝั่งเซิร์ฟเวอร์จะ FAIL ทั้งกลุ่ม (เจอจริงตั้งแต่ Module 05)
- exit code ไหนถึงปล่อยได้? — 0 เท่านั้น และต้องเป็นค่าที่คำสั่งจบล่าสุดจริง ไม่ใช่ค่าจำ
